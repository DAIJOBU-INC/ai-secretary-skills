# 会議のセットアップ — 事実カード → 重複確認 → 足りない側だけ作る

チャット（Slack／Teams など）で決まった打ち合わせを、カレンダーの予定と議事録ページにする。
1回の依頼で作る会議は1つ。**すでにあるものが優先。** 既存の予定やページを、チャットに合わせて勝手に直さない。

`mtg-prep` との違い: こちらは会議の「枠」を作る（日時・参加者・招待・議事録ページ）。中身の準備資料は `mtg-prep`。

## 1. 事実カードを作る（書き込む前に必ず）

関係するチャンネル・スレッドだけを読み、次を1枚にまとめる。チャットが読めなければ、該当部分を貼ってもらう。

- 会議名と目的
- 開始日時（日付は `YYYY-MM-DD` で。「明日」「来週火曜」は今日の日付から計算する）
- 終了時刻または長さ
- 参加者（名前と、確認できたメールアドレス）
- 根拠にしたメッセージ（リンクか日時）
- 分からないこと

**推測で埋めない。** メールアドレス・長さ・参加者が分からなければ「未確認」と書く。開始時刻は分かるのに長さが分からないときは、予定を作る前に1回だけ聞く。

## 2. 重複を2か所で確かめる

### カレンダー

その日の前後を検索し、会議名・時刻・目的・参加者を比べる。言い回しが違っても、日時と目的が同じなら同じ会議とみなす。

すでにあるとき:
- カレンダーには何も書かない
- 招待を送り直さない。参加者を足さない・消さない
- 会議リンクを作り直さない。題名・時刻・説明を変えない

### 議事録ページ

CLAUDE.md に議事録の置き場（Notion のデータベースなど）が書いてあればそこだけを、日付と会議名で探す。書いていなければ `work/mtg/YYYYMMDD_[会議名]_会議メモ.md` を探す（議事録は終わったあとに `meeting-notes` が別のファイルで作るので、名前をかぶらせない）。
ページがすでにあり、「この会議で決めること」が書いてあれば、何も書かない。空で、本人が議事録の準備まで頼んでいるときだけ、下の「この会議で決めること」だけを足す。ほかの項目には触らない。

## 3. 足りない側だけ作る

| カレンダー | 議事録ページ | 本人の依頼 | 動き |
|---|---|---|---|
| ある | ある（決めること記入済み） | どれでも | 何も書かない |
| ある | ある（決めること空） | 議事録の準備まで | 「この会議で決めること」だけ足す |
| ある | ない | 議事録ページを作って | ページだけ作る |
| ない | ある | 予定を入れて・登録して | 参加者なしの自分の予定だけ作る |
| ない | ある | 招待して | 宛先を見せて OK をもらってから、参加者つきの予定を作る |
| ない | ない | 確認だけ・準備だけ | 何も書かない。事実カードを見せる |
| ない | ない | 両方作って | それぞれ1つずつ作る（招待は上と同じく、頼まれて宛先の OK をもらってから） |
| 上に無い組み合わせ | | | 何も書かず、事実カードを見せて聞く |

カレンダーに書き込めない環境なら、事実カードを予定に貼れる形で出して止まる。

## 招待を送るのは、はっきり頼まれたときだけ

- カレンダーに参加者を入れると、その場で招待メールが飛ぶことがある
- 「登録して」「カレンダーに入れて」は、**参加者を入れない自分の予定**として作る
- 参加者を入れるのは、本人が今「招待して」「送って」と言い、宛先（名前・アドレス）を見せて OK をもらってから
- 既存の予定を直すと、招待が送り直されることがある。今の予定を見せて「直して」と言われてから直す
- 過去のチャットや、このスキルの存在は許可にならない。許可は今の依頼だけ

## 議事録ページの「この会議で決めること」

作る・足すときは、この1ブロックを入れる。

```
この会議で決めること
・<会議で決めること・確かめることを、1〜3行で>
```

- 「〜を決める」「〜を確認する」「〜を整理する」の形にする
- 例: `・新しい見積もりの型を、来月から使うか決める`
- 司会の台本・担当・期限・空欄の項目は足さない。チャットから1行も書けないときは、1つだけ聞いて何も書かない

## 最後に伝えること（4点）

- すでにあって何もしなかったもの
- 作ったもの
- 確かめたこと
- まだ分からないこと・本人に決めてほしいこと

**招待を送ったか・送り直したかは、送っていなくても必ず書く。**

## Gotchas（過去にハマったケース）

1. **言い回しが違う同じ会議を、別の会議として二重に作る**: 「定例」「週次MTG」のように題名が違っても、日時と目的が同じなら同じ会議。作る前に必ず日付で検索する
2. **「そろえておこう」で既存の予定を直し、全員に招待が送り直される**: 既存の予定は、頼まれない限り1文字も直さない
3. **チャットに無い参加者やメールアドレスを、推測で補いそうになる**: 確認できたアドレスだけを使う。分からない人は「未確認」にして聞く
4. **「この会議で決めること」を盛りすぎて、誰も読まない議事録になる**: 1〜3行で十分。推測で小見出しや担当を足さない
