# 工程表 — 今日を始める前に組み立てる

今日、または明日の予定を15分刻みの工程表にする。カレンダー・タスク管理ツール・前日の日報の持ち越しを材料に、重い仕事と会議がぶつからないように並べる。準備が要りそうな会議は知らせ、1on1は準備資料も自動で作る。

会議そのものの準備資料を作るのは mtg-prep（このパック）。本スキルは1日の工程表の中で「準備が要るかどうか」を示すところまで。

## 使い方

`$ARGUMENTS` に「明日」「tomorrow」を渡すと翌日分を作る。指定が無ければ今日分を作る。

## 手順

1. **対象日を決める**: 引数が「明日」「tomorrow」→ 翌日。それ以外（引数なし含む）→ 今日。
2. **材料を集める**（つながっているものだけ使う。つながっていないものは黙って飛ばさず「使えなかった」と書くか、貼ってもらう）

   | 材料 | 内容 | 使えない・無いとき |
   |---|---|---|
   | カレンダー（Google カレンダー／Outlook など） | 対象日の予定（時間・参加者・場所） | 予定を貼ってもらう |
   | タスク管理ツール（Notion／Linear／GitHub Issue など。つながっていれば） | 未着手・進行中タスクのうち対象日が期限のもの | この節を「未接続」として省く |
   | 前日の日報 | daily-log（このパック）が書いた「持ち越し」。work/daily/ の日報ファイルを日付の新しい順に探し、一番新しいものから読む（週明けなら金曜の日報になる） | 無ければ今日から始める |
   | メール（Gmail／Outlook など）・チャット（Slack／Teams など） | 対象日が期限の約束・確認事項（明日モードで特に効く） | 貼ってもらう |

3. **会議ごとに準備の要否を見る**: 参加者に社外の相手が含まれる会議、またはタイトルに「キックオフ」「初回」等が入っている会議を「準備が要る会議」として扱う。
   - work/mtg/ にその会議の準備資料（`YYYYMMDD_[会議名]_準備資料.md` など、mtg-prepの保存形式）が無いか確認する
   - 無ければ、対話実行時は「mtg-prepで準備資料を作りますか？」と聞く。定期実行（無人）時は聞かずに「### 要確認」に書いて先へ進む
   - 予定タイトルに「1on1」「ワンオンワン」「1:1」が入っている、またはメンバーのファイル（`context/members/` があれば）と同じ名前が入っている予定を見つけたら、そのメンバー名で mtg-prep を呼ぶ。1on1かどうかの詳しい判定・資料の中身は mtg-prep側の仕事なので、ここでは呼ぶかどうかだけ決める（同じ判定を2箇所に書かない）
4. **タスクを仕分ける**: 緊急度×重要度（アイゼンハワー・マトリクス）と認知負荷（高＝設計・分析・判断／中＝実務作業／低＝事務）の2軸で仕分ける
5. **工程表を組む**: 動かせない予定（会議）を先に固定し、空いている枠を認知負荷の高い仕事から午前優先で埋める。午後は会議・事務作業を優先配置する
6. 明日モードの場合: 辞退済みの予定は取り消し線で表示し、空き時間を算出する
7. `work/daily/YYYYMMDD_工程表.md` に保存する（保存先はCLAUDE.mdに別の指定があればそちらを優先する。フォルダが無ければ作る）

## 組み方の原則

午前に認知負荷の高い仕事、午後に会議・事務作業を置く。人は午前のほうが集中力が高く、会議で分断されると重い仕事に戻りにくいため。動かせない会議の時間帯を先に固定し、空いている枠を仕事の重さで埋める。

## 出力形式

```
## YYYY-MM-DD（曜日）の工程表

### 午前
| 時間 | タスク | カテゴリ | 認知負荷 |
|------|--------|----------|----------|

### 午後
| 時間 | タスク | カテゴリ | 認知負荷 |
|------|--------|----------|----------|

### 今日が期限のタスク（タスク管理ツール）
- [ ] 内容（期日: YYYY-MM-DD）

### 準備が必要な会議
- 会議名 — 準備資料: あり（work/mtg/…）／ なし

### 持ち越し（前日の日報より）
- [ ] 内容

### 空き時間（明日モードのみ）
| 時間帯 | 利用可能時間 |
|--------|-------------|

### 明日の連絡事項（明日モードのみ）
- メール・チャットで見つかった約束・リマインドを1〜3行で（例:「◯◯への返信期限」「△△の準備物」）

### 要確認
- 定期実行で判断を保留した項目、材料が集まらなかった項目
```

## ルール

- 会議の時間帯はカレンダーを正とする。他の材料と食い違ったらカレンダーを優先する
- 準備資料を作るかどうかは対話実行時だけ聞く。定期実行では聞かずに「要確認」に書いて進める
- 1on1の判定ロジックはここで作り込まない。mtg-prepに任せる

## 定期実行にするなら

始業前に自動で回すと、出社時には工程表ができている状態になる。使える環境ならスケジュール機能で「平日の朝◯時」に登録する（具体的な設定方法はお使いの環境のスケジュール機能を確認する）。定期実行では準備資料を作るかを質問できないため、「要確認」に書いて止まらずに進める。

## Gotchas（過去にハマったケース）

1. **持ち越しを毎日そのまま転記すると増え続ける**: 前日の日報の持ち越しを機械的にコピーするだけだと、同じ項目が何ヶ月も残ることがある。タスク管理ツールがあれば早めに起票して工程表から外し、無ければ同じ項目が3日以上残っていないか目視で確認する
2. **つながっているカレンダー全部を律儀に見に行かない**: 他のメンバーの個人カレンダーは権限次第でタイトルが見えず、予定の有無の帯しか取れないことが多い。自分の予定が入っているカレンダーだけで足りることが多い
3. **議事録ツールを対象日そのもので検索すると空振りする**: 今日・明日の分はまだ議事録が存在しないため、日付検索は必ず0件になる。参加者名・会議名で検索し、過去の関連ミーティングを引き当てて紐づける
4. **タスク管理ツールの接続が切れているときは黙って飛ばさない**: 取得に失敗したら「⚠️未接続（期限タスク抽出不可）」と明記して続行する。認証エラーが出た状態で粘りすぎない
