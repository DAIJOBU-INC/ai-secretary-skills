# 企業カルテの型

`context/clients/<相手先>.md` がまだ無い会社を調べるときは、この形で新規作成する。既にある場合はこの型に沿って追記・更新する（丸ごと書き直さない）。

```markdown
---
updated: YYYY-MM-DD
---

# <会社名>

## 基本情報

| 項目 | 内容 | 出典・確認日 |
|---|---|---|
| 正式名称 | | |
| URL | | |
| 所在地 | | |
| 設立 | | |
| 事業内容 | | |
| 規模（従業員数・売上等） | | |

## 実績・実体の確認

相手の説明・数値を、裏付けの強さで4つに分けて書く。自己申告だけの情報は「資料で確認」に数えない。同じ情報の転載（同じプレスリリースが複数サイトに載っているだけ等）も、別々の根拠としては数えない。

| 相手の説明・主張 | 分類 | 出典・確認日 |
|---|---|---|
| [例: 導入実績500社] | 資料で確認／自己申告／未確認／資料間で矛盾 | |

- **資料で確認**: 公式サイト・登記情報・報道など、独立した情報源で裏が取れたもの
- **自己申告**: 相手の説明・相手が出した資料のみで、外部の裏付けが無いもの
- **未確認**: まだ調べきれていないもの（検索していない場合は結果欄に「調べていない」と理由を書く）
- **資料間で矛盾**: 情報源同士で内容が食い違うもの

## 業界・周辺情報

- 業界内の位置づけ
- 直近のニュース・プレスリリース（あれば日付つきで）

## 社内の既存接点

メール・チャット・議事録ツールでの過去のやり取りがあれば記載する。無ければ「接点なし」と書く（悪い意味ではなく、単に初接点という記録）。

## 推測で書いた点・未確認事項

「実績・実体の確認」の表に入らない、その他の推測・未確認点をここに書く。事実と推測をはっきり分ける。

- 推測: [〜と考えられる]（根拠: 〜）
- 未確認: [裏が取れなかった点]

## ネクストアクション

- [ ] 次に確認すべきこと
```

## 書き方の注意

- 各表の「出典・確認日」列は空欄にしない。確認していない項目は空欄より「未確認」と書く方が、後から見た人に伝わる
- 数字（売上・従業員数等）は出典の年度・時点を必ず添える。古い数字をそのまま今の数字として使わない
- 「推測で書いた点・未確認事項」は削らない。分かったことだけを並べると、後で読んだ人が「全部裏が取れている」と誤解する
- 「社内の既存接点」が薄い・無いことは、それ自体が「関係が良くない」という意味ではない。単なる事実として書く
