# しくみ絵本 デザインシステム

シリーズの意匠を固定するための仕様。絵本らしさは「丸い形・顔モチーフ・コマ送り」の造形で出す。
下のパレット・フォントはそのまま使える既定値。自分のブランドカラーやフォントがあれば、同じトークン名のまま値だけ差し替えてよい。

## パレット（CSSトークン）

ライトが正、ダークは同名トークンの差し替えのみ（コンポーネント側でテーマ分岐はしない）。下のダーク値は Dark Navy `#0b1220` を地に各色を明るく持ち上げた例。

| トークン | ライト | ダーク | 役割 |
|---|---|---|---|
| `--paper` | `#f5f7fa` | `#0b1220` | ページの地 |
| `--panel` | `#FFFFFF` | `#151d33` | 図パネル・紙面（地より一段明るい面） |
| `--ink` | `#1a1e2e` | `#e8ebf3` | 本文（純黒・純白は使わない） |
| `--ink-soft` | `#5a6070` | `#98a2b8` | 補足・キャプション |
| `--line` | `#e8eaed` | `#2a3350` | 罫線・ダミーテキスト |
| `--blue` / `--blue-soft` | `#2563eb` / `#eff6ff` | `#7aa7f7` / `#1c2a4a` | ことば系キャラの色（例: カード・貼り紙） |
| `--green` / `--green-soft` | `#188038` / `#e7f2ec` | `#6cc394` / `#1d3226` | 道具・容器系キャラの色（例: 道具箱） |
| `--amber` / `--amber-soft` | `#ea580c` / `#fdeee6` | `#ff9d66` / `#3a2517` | 運搬・合図系キャラの色（例: 宅配便）・**番号チップ** |
| `--navy` / `--navy-soft` | `#0d1b3e` / `#e9ecf3` | `#b4c0dc` / `#232c47` | 機械・しくみ系キャラの色（例: からくり） |
| `--stamp` | `#d93025` | `#ff8075` | **警告専用**。「ダメ！」「〜しないで」の文言だけに使う。番号チップ・装飾には使わない |

- 新しいキャラの色は上の並びから選ぶ（脈絡なく新色を増やさない）。`-soft` は該当色の約8%ティント
- フラット塗り（影・装飾グラデーションは禁止）。原色の大面積塗りは避けてTint中心に。強い色（警告色以外）は1セクション1箇所目安

## 絵本らしさの決まりごと

- **彩り帯**: ページ最上部に高さ6pxのグラデーション帯（例: `--navy` → `--blue`。ヒーロー用途のみ・本文装飾には使わない・ダークでも同値）
- **h1 下線バー**: h1 直下に 48×5px・アクセント色の丸角バー
- 「紛らわしさの正体」帯（`.same`）は Tint 地＋点線囲い
- 警告文（`--stamp`）と番号チップ（`--amber`）を混同しない

## タイポグラフィ（既定値。使えるフォントに置き換えてよい）

- 見出し・本文・図中テキスト: 和文ゴシック（例: Noto Sans JP の 400/500/700/900）
- 欧文アイキャッチ（eyebrow等の短い英字ラベル）: 欧文サンセリフ（和文フォールバック必須）
- パス・コードの表記: 等幅フォント（例: JetBrains Mono → 無ければ Roboto Mono）
- 本文16px／line-height 1.9。見出しは可変サイズにし、不自然な折り返しにならないよう `text-wrap: balance` 等で調整する

## ベースCSS（コピーして使う）

テーマ切替は「素の `:root` にライト全定義 → `@media (prefers-color-scheme: dark)` 内の `:root:not([data-theme="light"])` でトークン再定義 → `:root[data-theme="dark"]` で同内容」の3段構成にする。色の定義がメディアクエリの中にしかない状態を作らない。`body` の背景は必ず `var(--paper)` を明示する。

構成部品（クラス名の例）: `.band`（最上部の彩り帯）／ `.book`（本体、max-width 860px程度）／ `.eyebrow` ／ `h1`（キャラ色のspan＋下線バー）／ `.lead` ／ `figure`＋`figcaption`（パネル囲い・角丸20px）／ `.same`（Tint地の「紛らわしさの正体」帯）／ `.chip`（アクセント色の丸数字）／ `.sec-head` ／ `.table-wrap`＋`table`（早見表。`overflow-x:auto` 必須）／ `.note`（脚注）。

## 図（インラインSVG）の作法

- `viewBox="0 0 760 H"`・width 100%。色は必ず `var(--トークン)` で指定する（リテラル色は使わない）
- 図中テキストは12px相当以上・3語以内。左右2列比較は中央に `stroke-dasharray="2 8"` の点線仕切りを入れる
- キャラの顔は「点2つ＋Qカーブの笑み」で統一する（絵本感のモチーフ。ヒーロー図では必ず、他の図ではお好みで）
- 矢印は `polygon` の三角。強調矢印は太線9px、通常は3.5px
- `role="img"`＋`aria-label`（図の主張を1文で）を必ず付ける
- **テキストのはみ出しに注意**: 日本語は1文字≒font-size幅で場所を取る。ラベルが viewBox 右端や隣の矩形に届かないか、描画前に座標を暗算する

## うごきのコマ送り（紙芝居）の作法

構造図が「かたち」を、コマ送りが「時間」を受け持つ。1絵本に必ず1枚入れる。

- 横1列に3〜4コマ。各コマ = パネル色の角丸パネル（幅170前後）＋左上に丸数字（アクセント色・小さめ）＋パネル下にひとことラベル（12.5px・7字以内）
- コマ間は太めの右向き矢印。最終コマだけ結果をキャラ色のTint地で強調する
- **同じキャラ絵を全コマで使い回し、位置・開閉・表情だけ変える**（コマごとに絵柄が変わると時間の流れに見えなくなる）
- 題材は「読者が実際にやる1回の操作」にする（例: ボタンを押す→画面が変わる→結果が出る→次に進む）。抽象概念の遷移ではなく、操作の実況にする

## キャラ⇔ほんとの名前 対応表の作法

おとなの早見表の直前に置く小さな3列表。ここだけは正式用語が主役になる。

| 列 | 中身 |
|---|---|
| キャラ | 絵本内の呼び名（キャラ色の太字） |
| ほんとの名前 | 正式用語（`code` 表記。検索できる文字列にする） |
| ひとこと | 15字以内の定義 |

## 印刷用CSS（ベースCSSの末尾に必ず入れる）

画面表示には影響しない。これが入っていればPDF書き出しが1コマンドで済む。印刷は常にライト・白地にする（インク節約のため `--paper` も白に落とす）。

```css
@media print {
  :root, :root[data-theme="dark"] {
    --paper: #FFFFFF; --panel: #FFFFFF; --ink: #1a1e2e; --ink-soft: #5a6070;
    --line: #e8eaed; --blue: #2563eb; --blue-soft: #eff6ff;
    --green: #188038; --green-soft: #e7f2ec; --amber: #ea580c; --amber-soft: #fdeee6;
    --navy: #0d1b3e; --navy-soft: #e9ecf3; --stamp: #d93025;
  }
  body { background: #FFFFFF; }
  figure, .same, .table-wrap { break-inside: avoid; }
  .sec-head { break-after: avoid-page; }  /* 見出しだけページ末尾に残る「孤児見出し」防止 */
  section { margin-top: 40px; }
  a { color: inherit; }
}
@page { size: A4 portrait; margin: 13mm 15mm; }
```

## PDF書き出し（オプション・「紙でほしい」と言われたら）

Chromeが使える環境なら、headlessモードで1コマンドでPDF化できる。

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"  # Windowsでは chrome.exe のパスに読み替える
"$CHROME" --headless=new --disable-gpu --no-pdf-header-footer --print-to-pdf=ehon.pdf "file://$PWD/本体.html"
```

1. 書き出したPDFを開き、図やパネルがページ境界で切れていないか全ページ確認する
2. 切れていたら、その要素を含むセクションの直前に `<div style="break-before: page"></div>` を入れて再書き出しする
3. ファイル名は `しくみ絵本_<タイトル>.pdf` にして渡す

## 公開前検証（できる環境なら・任意）

1. `printf '<html data-theme="dark">' > dark-test.html && cat 本体.html >> dark-test.html` でダーク強制版を作る
2. headless Chromeで両方をPNG化する: `"$CHROME" --headless=new --disable-gpu --window-size=900,4700 --hide-scrollbars --screenshot=out.png "file://$PWD/本体.html"`
3. PNGを目視して、文字のはみ出し・要素の被り・コントラストを修正 → 再レンダリングで確認 → 公開

headless Chromeが使えない、または手間をかけたくない場合は、ブラウザで直接開いてライト/ダーク両方を目視確認するだけでもよい。

## Gotchas（過去にハマったケース）

1. **図の中の日本語ラベルはすぐ枠からはみ出す**: 日本語は1文字≒font-size幅で場所を取る。描画前に座標を暗算して余裕を見る
2. **構造図だけだと「動き」が伝わらない**: 比較・分類の図だけでは「かたちは分かるが、実際どう使うのか」が読者に残る。必ず1枚は時間の流れ（コマ送り）を見せる
3. **headless Chromeがスクリーンショット後に終了しないことがある**: バックグラウンドで起動し、PNGができたら該当プロセスだけ止める。普段使っているChromeのプロファイルと衝突しないよう、検証用に専用の `--user-data-dir` を切っておくとよい
4. **縦長PNGの単純な切り出しはズレることがある**: OS標準の画像ツールより、Pythonの画像ライブラリ（PillowのImage.cropなど）で切る方が正確
