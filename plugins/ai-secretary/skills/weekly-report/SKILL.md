# 週次レポート — 1週間の日報を束ねる

その週の日報（daily-log が書いたもの）を束ねて、経営の定点観測に使えるレポートにする。毎日の記録は daily-log（このパック）、本スキルは1週間分を束ねる係。

## 使い方

引数無し。週の終わり（金曜）または週明け（月曜、もしくは土日）に実行する想定。対象期間は実行日に応じて自動で決める（手順1）。

## 手順

1. **対象期間を決める**: 実行日が火曜〜金曜なら、今週の月曜〜実行日を対象にする。実行日が月曜、または土曜・日曜（週明け実行）なら、前の週の月曜〜金曜を対象にする（土日に作業記録があれば対象期間に含める。無ければ含めなくてよい）
2. **日報を集める**: `work/daily/` から対象期間内の日報ファイル（`YYYYMMDD_日報.md`）を集める
3. **無い日を補う**: 日報が無い日は、カレンダー・議事録ツール・メール・チャット（つながっていれば）から会議実績とやり取りを拾って代わりに使う。**補った日は必ずレポートに明記し、何を根拠に補ったかも一言添える**。それでも何も見つからない日（祝日等）は「日報なし」とだけ書き、無理に埋めない
4. **今週の材料を集める**（つながっているものだけ使う。つながっていないものは黙って飛ばさず「使えなかった」と書く）

   | 材料 | 内容 | 使えない・無いとき |
   |---|---|---|
   | タスク管理ツール（Notion／Linear／GitHub Issue など） | 今週完了・進行中のタスク | この節を「未接続」として省く |
   | カレンダー | 来週月〜金の予定（来週の予定セクション用） | 来週の主要な予定を教えてもらう |
   | context/company/decisions.md | 今週の日付で追記された判断（あれば） | 無ければこの材料は使わない |

5. **レポートを組む**: 日報の「完了」を束ねて「今週の成果」にする。「進行中」を束ねて「進捗」にする。複数日にまたがって残っている持ち越しと、日報の「気づき・判断したこと」に課題として書かれていたものを合わせて「課題」にする。「気づき・判断したこと」と decisions.md の今週分から「判断したこと」を作る。来週のカレンダーと優先タスクから「来週の予定と注力」を作る
6. **今週の数字を作る（あれば）**: 追っている指標をまとめたファイル（例: `context/company/kpi.md`。CLAUDE.mdに別の場所の指定があればそちら）があれば、主要な指標の今週の値と前週比を「今週の数字」にする。前週データが無い指標は「比較不可」と書き、推測の数字は入れない。ファイルが無ければこの節ごと省く。人に渡す・貼るときは、この節だけ外すか渡してよいか確認する（数字は機密度が高いことが多い）
7. `work/weekly/YYYYMMDD_週次レポート.md` に保存する（保存先はCLAUDE.mdに別の指定があればそちらを優先する。フォルダが無ければ作る）

```
# 週次レポート YYYY年 MM/DD週（MM/DD - MM/DD）

対象期間: MM/DD（曜）- MM/DD（曜）
日報が無かった日: MM/DD（カレンダー・メールから補いました）※無ければこの行は省略

## 今週の成果
- 

## 進捗
- 

## 課題
- 

## 判断したこと
- 

## 来週の予定と注力
- 

## 今週の数字（あれば）
- 指標名: 今週の値（前週比: +/-／前週データが無ければ「比較不可」）

## 要確認
- 材料が集まらなかった項目、補完の根拠が薄い項目
```

## ルール

- 日報が無い日を補ったら、必ずレポート内に明記する。黙って埋めない
- 経営の定点観測として使うものなので、良かったことも課題も両方書く。良いことだけに寄せない
- 金額・契約条件・「今週の数字」など機密度の高い数字を扱う場合は、レポートの配布範囲を確認してから書く。特に「今週の数字」は人に渡す・貼る前に、その節を外すか確認する（Gotcha「先週データが無い指標を無理に埋めない」も参照）

## 定期実行にするなら

金曜の夕方に自動で回すと、週の振り返りが習慣として定着しやすい。使える環境ならスケジュール機能で「毎週金曜◯時」に登録する。定期実行では日報の抜けを確認なしで補うため、「日報が無かった日」の明記を省かない。

## Gotchas（過去にハマったケース）

1. **タスク管理ツールは名前だけで探すと別のダミーデータを拾うことがある**: 似た名前のテンプレートや見本データが別にあると、名前検索で誤ったものを拾う事故が起きうる。IDやURLなど一意に決まる指定ができるなら、名前検索より優先する
2. **先週データが無い指標を無理に埋めない**: 先週との比較を書くときに前週分のデータが無ければ「比較不可」と明記し、推測の数字を入れない
3. **定期実行の環境は時刻の基準が日本時間と違うことがある**: 実行環境によっては世界標準時（UTC）が基準になっていることがある。月曜〜金曜の範囲がずれないよう、日本時間を明示して日付を計算する
4. **情報収集の一部が失敗しても、レポート自体は必ず作る**: 収集できた内容が乏しくても「取得失敗」と明記した上でレポートを出す。情報が無いことを理由にレポート自体を作らないと、その週の記録が丸ごと欠ける
