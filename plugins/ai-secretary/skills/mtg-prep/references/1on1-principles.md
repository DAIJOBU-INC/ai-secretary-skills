# 1on1設計の理論的基盤

1on1は「話を聞いてあげる場」ではない。部下が自分の頭で考えるための時間を、上司が設計する場。

## 理論的基盤

- **経験学習サイクル**（デービッド・コルブ / ヤフーの1on1）: 具体的経験 → 内省（振り返り） → 教訓を引き出す（概念化） → 新しい状況への適用。1on1はこのサイクルの「内省→概念化」を上司が質問で促進する場
- **進捗の法則**（テレサ・アマビール）: やりがいのある仕事が進捗するよう支援することが最重要。小さな進捗を認識し承認することがモチベーションの源泉
- **Radical Candor**（Kim Scott）: 「個人的に思いやる」×「直接的に指摘する」の両立が目標。思いやりだけで指摘を避ける「破滅的共感」が最も多い失敗パターン
- **メタファシリテーション**（中田豊一『「なぜ」と聞かない質問術』）: 「どう思う？」「どうしたい？」といった**「どう質問」を原則として使わない**。理由は「質問をつくる努力をせず、回答を相手に丸投げしている」から。上司側が前提を絞り込んで質問をつくる責任を持ち、**事実質問**（誰が・いつ・何と言ったか）で解釈のズレを浮かび上がらせる

## 機能する1on1の3つの役割

1. 信頼の地盤を作る — 日常では出ない本音や迷いが出る場所
2. 課題の早期発見 — 問題が大きくなる前に小さなサインをキャッチする
3. 成長を設計する — 部下自身が気づいていない課題や強みを対話で引き出す

## 5つのコミュニケーション技法（ヤフーの1on1）

1. アクティブリスニング — 最後まで聴ききる。うなずき・相槌・キーワードの繰り返し
2. レコグニション — 存在の承認。「あなたの存在を認めている」というメッセージ
3. コーチング — 答えを示さず、質問で自力の答えをサポート
4. ティーチング — 知識不足の場面では教える（コーチングでは対応できない時）
5. フィードバック — 行動が周りからどう見えているかを「鏡」として伝える

## すり合わせ9ボックス（世古詞一）

縦軸: 業務 / 個人 / 組織 × 横軸: 過去 / 現在 / 未来 の9マスで対話テーマを網羅的にカバーする。業務×現在（進捗確認）だけに偏らないよう、個人×未来（キャリア）や組織×現在（チームの課題）も扱う

## Andy Groveの1on1設計（HIGH OUTPUT MANAGEMENT）

- 1on1は「部下のミーティング」。アジェンダと雰囲気は部下が設定する
- 本音の話題は20〜30分経過してから出てくる傾向がある
- 「部下がその話題について言い尽くしたと上司が思った時、もう一つ質問をすべきだ」

## NGパターン（準備資料でこれらを防ぐ）

- 進捗確認だけで終わる → 1on1は「業務の話」ではなく「人の話」をする場
- アドバイスしすぎる → 7割は部下に話させる。上司の発言は質問中心にする
- 前回の内容を覚えていない → 前回ログを必ず振り返りに入れる
- ポジティブなことしか言わない → 耳の痛いフィードバックも準備する（Radical Candor: 破滅的共感に陥らない）
- すぐ答えを教えてしまう → "Stay curious a little longer"（The Coaching Habit）
- **前提を共有せずに「で、どうしたいの？」と投げる** → 丸投げ。相手は「どうしたいか」ではなく「状況が分からない」状態で固まり、上司の自己満足で終わる。投げる前に前提を共有したか自問し、代わりに「今わかっている事実を3つ挙げて。それから解釈を聞かせて」と絞り込む
