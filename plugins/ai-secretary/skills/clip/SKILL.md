# クリップ — URL要約保存

URLを受け取り、内容を要約・タグ付けして `work/clips/YYYYMMDD_clip_<題名>.md` に保存するスキル。
記事のネタ元、業界動向の把握、判断材料の置き場になる。

## 引数

`$ARGUMENTS` に1つまたは複数のURLをスペース区切りで指定できる。
未指定の場合は「クリップしたいURLを教えてください」と聞く。

例:
```
/clip https://example.com/great-article
/clip https://x.com/user/status/123 https://example.com/another
```

## 実行手順

1. **URL判定**: 各URLについてタイプを判定する
   - X/Twitter（x.com, twitter.com）→ `source: x`
   - GitHub リポジトリ/Issue/PR → `source: github`
   - PDF URL → `source: pdf`
   - その他 → `source: article`

2. **内容取得**:
   - 通常のWebページ・GitHub・PDFは、Web取得ツールで本文を取得する
   - X/Twitter やログイン必須のページ（有料記事・会員限定ページなど）は取得ツールで本文が取れないことが多い。取れなかったら、何度も取得を試す前に「本文を貼ってください」とユーザーに頼む
   - 取得はできたが内容が薄い・エラーページだった場合も同様に本文を貼ってもらう

3. **要約+タグ生成**（日本語）:
   - 要約: 3〜5行
   - キーポイント: 3〜5個
   - 原文の重要な引用: 1〜2箇所（元記事より十分短く。長い引用はしない）
   - タグ: 3〜5個（小文字・ハイフン区切り、例: `ai`, `marketing`, `management`）
   - **あなたの仕事への応用**: この情報があなたの事業・仕事にどう使えるか1〜3行

4. **ファイル保存**: `work/clips/YYYYMMDD_clip_<題名>.md`
   - 題名: タイトルから短い日本語、または英小文字ハイフン区切りで生成（目安40文字以内)
   - 重複ファイル名は `_2`, `_3` サフィックス

5. **インデックス更新**: `work/clips/_index.md` の `<!-- CLIPS_LIST_START --> 〜 <!-- CLIPS_LIST_END -->` の間に1行追記する（`_index.md` が無ければ、このマーカーを含む形で新規作成する）
   ```
   - [YYYY-MM-DD] [タイトル](YYYYMMDD_clip_<題名>.md) — 一言要約 #tag1 #tag2
   ```

6. **ユーザー応答**（プレーンテキスト、簡潔に）:
   ```
   📎 クリップ完了: N件
   - YYYYMMDD_clip_<題名>.md  タイトル  #tag1 #tag2
   ```

## クリップファイルのフォーマット

```markdown
---
date: YYYY-MM-DD
type: clip
source: x | article | github | pdf
url: https://...
author: （わかれば）
tags: [tag1, tag2, tag3]
---

# タイトル

## 要約
（3〜5行）

## キーポイント
- ポイント1
- ポイント2
- ポイント3

## 原文メモ
> 重要な引用

## あなたの仕事への応用
- （記事執筆ネタ / 事業戦略のヒント / 競合動向 / 採用ブランディング等）

## 関連
<!-- 関連する context/ や 他クリップへのリンクがあれば -->
```

## 重要ルール

- **機密情報は書かない**: 顧客名・金額・パスワードやAPIキーなど
- **著作権配慮**: 原文を全文コピーしない。要約は元記事より十分短くし、引用は最小限に留める（長い引用はしない）
- **日本語で要約する**

## Gotchas（過去にハマったケース）

1. **ログイン必須のページは取得ツールで失敗しやすい**: X/Twitterや会員限定記事は、通常のWeb取得ツールでは本文が取れないことが多い。失敗を何度も繰り返す前に、早めに「本文を貼ってください」と頼んだほうが早い
