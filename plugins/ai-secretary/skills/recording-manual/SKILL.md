# 画面録画から手順書 — 初めての人が成功画面までたどり着ける形に

ゴールは「きれいな資料」ではなく、**初めて触る人が、上から順にやって成功画面までたどり着けること**。
録画に映っていないことは推測で埋めない。

## 最初に確かめること（録画と読み手の環境の違い）

依頼・録画・手元の資料から先に読み取り、分からないものだけ聞く。

- 誰が読むか、何ができるようになればいいか
- OS（Windows／Mac）、アプリかWeb版か、画面の言語、確認した日付
- 読み手の権限・必要な契約や接続（パスワードなどは写さない）
- 読み手が最初に見る画面、先に済ませておくこと
- 出す先（Markdown・Notion・既存マニュアルの修正）

録画の環境と読み手の環境を比べ、違うところ・分からないところを作業メモに残す。Windows の録画で Mac の手順は分からない。個人の有料アカウントの画面で、会社のアカウントの画面は分からない。

## 1ステップの型

どのステップも、この順で書く。

`どこから始めるか → 画面のどのボタン（見える名前） → 何をする・何を入れる → どんな画面になるか → 成功の見分け方 → うまくいかないときの戻り先`

- ボタンは「右上の青い『保存』」のように、名前と場所で書く。座標だけにしない
- 成功の見分け方は目に見えるもの（一覧に名前が出る・「完了」と表示される・ファイルが開ける）。「うまくいきます」は見分け方ではない
- 戻り先は、安全な画面と、やり直す前に確かめる1点。「アプリを閉じて最初から」を基本にしない
- 前のステップの終わりの画面と、次のステップの始まりの画面をつなぐ

## マニュアルの型

1. **目的**: なぜやるのか、できるようになることを短く
2. **分かれ道**: OS・立場などで手順が分かれるなら、最初に出して、関係ない手順を読ませない
3. **全体の流れ**: 図より先に `①②③` の文章で。「すでに入っている人はここで完了」のような早い出口も書く
4. **ステップ**: 見出しは `ステップ2｜インストーラーをダウンロードする（2分）` のように、やることと所要時間
5. **操作文の直下に、大きく読めるスクリーンショット**: 1画面に赤枠か「ここを押す」を1つ
6. **分かれ目**: 画面によって次が変わるところは、2つの結果を並べて書く
7. **完了**: 成功した画面そのものと、「これで完了です！」の一文
8. **困ったとき**: いちばん小さいやり直し方と、聞く先

- 1文に1つの操作。補足は別の行に `※` で書く
- 飾りの枠・絵文字は、目印に必要な分だけ
- 「録画では〜」「確信度」などの作り手のメモは、読み手のページに入れない

## スクリーンショットのルール

- 1つの操作に1枚。最初は場所が分かる広さで、慣れてきたら狭く切り抜く
- 本物の画面のまま。赤い四角か矢印で示し、ボタンの文字を隠さない
- **顧客名・人名・メールアドレス・ファイル名・日時は広めに隠してから**貼る。隠せないときはその画像を使わず、隠した版を本人からもらう
- 成功画面の1枚を必ず入れる。クリックだけで成功が見えないマニュアルは未完成
- 動画から画面を切り出すときは、使える環境なら ffmpeg などで場面ごとに切り出す。使えなければ、必要な画面のスクリーンショットを貼ってもらう

## 録画から分からないこと（推測で埋めない）

- カーソルもクリック先も映っていない操作
- 録画の外で済ませたログイン・権限・設定
- 成功画面が映っていないときの「成功」
- 実際にはやっていない送信・公開・共有・失敗時のやり直し

分からないまま残るところは作業メモに書き、足りない最小の録画・スクリーンショット・説明を1つだけ頼む。まだ確かめていない分かれ道がある間は、表紙に「録画準拠版（◯◯は未確認）」と書く。

## 次に録るときのお願い（今回の撮り直しは求めない）

- クリックの前に、カーソルをボタンの上に1秒置く
- 結果の画面を2秒映す
- 最後の完了画面まで映す
- 長い作業は区切って、番号付きのファイル名にする
- 通知を切り、関係ないタブ・メール・チャットを閉じる。見本の名前・データを使う
- 声が出せなければ、無音の録画＋5行のメモ（目的／操作した場所／入れた内容／できた状態／注意）でよい
- 口頭の説明は、会社で使ってよい文字起こし（録画ツールに付いているものなど）か、5行のメモでもらう

## 既存マニュアルの一部だけ直すとき

- 直すところと、その前後のつながりだけ直す。ボタン名が変わったなら、文とスクリーンショットと「どんな画面になるか」をそろえて直す
- 1文の修正で、録画の読み直しや全体の作り直しをしない
- 渡されたマニュアル（Notion など）は、直してと言われるまで読むだけ。丸ごと置き換える前に、今の中身を控えておく

## 保存

- Markdown で作るときは `work/manuals/<題名>.md`、画像は `work/manuals/<題名>/` に置く
- Notion など別の置き場が CLAUDE.md に書いてあれば、そちらを優先する
- Notion に画像を入れられないときは、Markdown＋画像フォルダで出し、貼り付けは本人がやる

## 守ること

- 元の録画は加工しない
- 会社やお客様の録画を、許可なく外部の文字起こしサービスに上げない
- 公開・共有・ログインは本人がやる

## Gotchas（過去にハマったケース）

1. **OS の分かれ道を後ろに書いて、関係ない手順まで読ませた**: インストール手順書で、Windows と Mac の違いを途中で書いていた。分かれ道を冒頭に出し、自分に関係ある手順だけ読めばいい形に書き直した。録画が無い側の手順は「未確認」にする
2. **飾りの枠や図が多く、どこを読めばいいか分からなかった**: 同じ手順書で、枠と図を減らし、①②③の文章で全体の流れを先に書く形にした。図が無くても意味が通るのが基本
3. **小さな全体のスクリーンショットと拡大図の2枚を並べて、かえって分かりにくくなった**: 場所が分かる広さの大きな1枚のほうが読みやすい
4. **ボタン名1つの修正で、全体を作り直そうとした**: 直すのは、その文とスクリーンショットと前後のつながりだけ
