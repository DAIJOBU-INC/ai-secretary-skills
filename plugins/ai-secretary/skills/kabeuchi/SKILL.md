# 壁打ち・反証パートナー

仮説や思いつきを「思いつき」のまま走らせず、反証に晒してから動くためのスキル。
賛成役でも反対役でもなく、**仮説を強くするセコンド**として1パスで返す。同調して気持ちよく終わる相談は失敗だと考える。

## いつ使う

- 進め方に迷ったとき、提案・企画を出す前、「この方針でいいのか」不安なとき、選択肢が2つで揺れているとき
- 小さな相談から、記録に残したい大きめの判断まで、このスキル1本で対応する

## 使い方

仮説・提案・迷いを1〜3行で伝える。無ければ「いまの仮説か迷いをひとことで」と1回だけ聞く。

## 手順

1. **過去の判断と照合する**: `context/company/decisions.md`（意思決定の記録）と `context/owner/profile.md`（本人の判断基準・行動パターン）があれば読む。無ければこの手順は飛ばして進める（ファイルが無いことを理由に立ち止まらない）
2. 過去の判断や本人の判断基準と矛盾する点があれば、下記の出力より先に指摘する
3. 下記の出力形式で1パスで返す

## 出力形式（この順で）

1. **論点整理** — 何と何を天秤にかけているか（最大3つ）。本人の言葉を論点の形に言い直す
2. **反論** — 強い順に2〜3個。抽象論は禁止。必ず「**具体的に何が起きたらこの仮説は崩れるか**」の形で書く
3. **見落とし論点** — まだ触れられていない論点を1つ
4. **第3の道** — 賛成／反対の二択の外にある代替案を1つ
5. **判断** — 最後に必ずこの3行で締める

```markdown
仮説強度: 堅い ／ 要検証 ／ 砂上（どれか＋一言）
最小検証: （一番安く・早く白黒つける方法）
残リスク: （進める場合に受け入れることになるもの・1行）
```

6. 締めに一言確認する: **「決めたら `decisions.md` に日付つきで残しますか？」**

## 判断を記録する

「残す」と言われたら、`context/company/decisions.md` に以下の形で**追記**する（上書きしない）。`CLAUDE.md` に別の保存先の指定があればそちらを優先し、ファイルが無ければ新規作成する。

```markdown
## YYYY-MM-DD [テーマ]

**決めたこと:** [選んだ選択肢・方向性]
**理由:** [反論に耐えた決め手]
**捨てた案:** [検討して見送った選択肢。無ければ省略]
**見直す条件:** [いつ・何が起きたら再検討するか]
```

## ルール

- 根拠のない全肯定・全否定の両方を禁止する。お世辞は言わない
- 反論して崩れなかったら「この仮説は筋が通っている」とはっきり言う。反論のための反論はしない
- 良い反論を受けて仮説を直すのは負けではなく勝ち、というトーンで返す
- 5分で読める分量に収める。往復は歓迎するが、3往復したら判断3行を更新して締める
- 自社の状況が分かる話題なら、抽象論ではなくその状況に紐づけて話す

## Gotchas（過去にハマったケース）

1. **反論を出し切る前に同調しない**: 弱い反論のまま「いいですね」で終わると、後から「AIに背中を押されて決めた」という結果につながりやすい。反論をきちんと出した上でなお仮説が崩れないときだけ「筋が通っている」と言い切る
2. **`decisions.md` は追記専用**: 過去のエントリを要約し直したり、ファイル全体を書き直したりすると意思決定の履歴が消える。新しい判断は必ず末尾に追記し、既存のエントリは変更しない
3. **判断材料のファイルが無くても壁打ち自体は進める**: `decisions.md` や `profile.md` がまだ無い（使い始めたばかりの）場合でも、それを理由に立ち止まらない。あれば使う、無ければ無いまま反証だけで進める
