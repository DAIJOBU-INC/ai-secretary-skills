# ダウンロード仕分け — 置くのではなく通す

ダウンロードフォルダは受信箱。届いたものは1週間以内に出口へ流し、直下にフォルダを作らない。
対象は Mac の `~/Downloads`。Windows では `%USERPROFILE%\Downloads` と読み替える。

## 出口ルール（例。実際の行き先はCLAUDE.mdの指定があればそちらを優先する）

| 届いたもの | 出口（例） |
|---|---|
| 見積書・請求書・領収書 | 経理関連のフォルダ |
| 契約書・覚書・NDA・合意書 | 契約書フォルダ |
| 履歴書・職務経歴書・面談メモ | 採用・人事フォルダ |
| 取引先ごとの成果物・ロゴ・素材 | 取引先ごとのフォルダ（`<取引先名>/` のように相手ごとに分ける） |
| 自社の完成資料・配布資料 | 資料フォルダ。クラウドドライブに同名・同サイズのものがあれば削除候補、無ければ資料フォルダに置いて「クラウド未保管」と報告 |
| 競合資料・受領資料・調査PDF | 調査フォルダ（テーマ別に分ける） |
| 作業用テキスト・小さな配布ファイル | 作業用プロジェクトフォルダの該当箇所（プロジェクト側に保存ルールがあればそれに従う） |
| 他所（プロジェクトフォルダ・保管庫など）に同一ファイル（md5一致）がある | 削除候補/重複 |
| 自動命名の画像（数字だけ・UUID・スクリーンショット連番等）、保存されたWebページ、インストーラ、テスト出力、旧版ビルド | 削除候補/{理由} |
| 個人の学習物・私用文書 | 個人用フォルダ |

- **迷ったら削除候補。** 削除候補は `~/Downloads/_削除候補_YYYYMMDD/{理由}/` に置く。ゴミ箱へ入れるのは本人
- 出口の実際のパスは環境ごとに違う。CLAUDE.md（やそれに類する設定ファイル）に保存先ルールが書いてあれば必ず従う。書いていなければ、初回だけユーザーに1回聞き、その回答をCLAUDE.mdに書いてよいか確認する
- 「(1)」「(2)」付きファイルは元ファイルとmd5比較する。同一なら重複、元が無ければ「(1)」を外してリネームして残す
- 残すものの名前は `YYYYMMDD_種別_内容`。日付や固有名が既に入っている資料はそのまま。UUIDの接頭辞は外す
- 機密性の高い書類（見積・契約・人事・決算など）は、個人アカウントに自動同期されるフォルダ（iCloud Drive、OneDriveの個人同期フォルダ等）へ安易に置かない。置き先に迷ったら確認する
- ブラウザ経由のファイル名はNFD（濁点が分離した形）のことがある。名前で同一判定するときは正規化（NFC）してから比較する

## 手順

1. **棚卸し**: `~/Downloads` 直下（サブフォルダは除く）を一覧し、7日以上前に作成・更新されたファイルを対象にする。ファイル名・サイズ・経過日数・拡張子・md5ハッシュ・（分かれば）他の場所にある同一ファイルの有無を一覧にする。専用スクリプトがあればそれを使い、無ければ `ls`／`find`／`stat`／`md5` 等の標準コマンドで作ってよい
2. **分類**: 出口ルールで1件ずつ判定する。判断がつかないものだけ中身を少し覗く（テキストは冒頭だけ、PDFは1ページ目だけ）。完成資料はクラウドドライブのコネクタが使えるなら検索し、名前とサイズが一致すれば「クラウド保存済み」として削除候補に回してよい
3. **提案**: 「ファイル → 出口 → 理由」の表と出口別の件数を出し、ユーザーの承認を取る（全部OK／一部変更／やめる、の3択にすると答えやすい）。**承認前には動かさない**
4. **移動**: 上書きしない移動（例: `mv -n`）で実行する。1件ごとに `~/Documents/_整理ログ/YYYYMMDD_manifest_downloads-triage.tsv` のような場所へ `種別\tfrom\tto` を追記する。プロジェクトフォルダ（gitリポジトリ等）に入れたファイルは、そのプロジェクト側の保存・共有ルールに従う
5. **報告**: 出口別の件数表、クラウド未保存の完成資料一覧、削除候補フォルダの場所を伝える

## やらないこと

- 直接削除・ゴミ箱直行・ファイルの上書き
- シンボリックリンクや、アプリが自動生成・管理しているフォルダ（会議ツールの録画保存先、インストーラの展開先など）は触らない
- `.env`・鍵・認証情報らしいファイルは開かず、存在だけ報告する
- クラウドドライブへのアップロードは本人がブラウザ等で行う（自動アップロードはしない）
- ダウンロード直下に受け皿フォルダを作って寝かせること（削除候補フォルダだけ例外）

## Gotchas（過去にハマったケース）

1. **良かれと思って承認前に動かすと信頼を失う**: 出口ルールに自信があっても、移動は必ず「提案→承認」の後にする
2. **同時に複数のセッション／ウィンドウで同じ整理をすると衝突する**: 着手前に、同じ整理を別のセッションで動かしていないか一声かける（使える環境ならセッション一覧などで確認する）
3. **「(1)」付きファイルを別物として扱うと重複が溜まる**: リネームだけの複製はmd5比較で必ず重複判定する
4. **完成資料をクラウド未確認のまま削除候補にすると、クラウドに上がっていない資料を消しかねない**: 名前とサイズが一致するまでは削除候補に回さず、資料フォルダに残して「クラウド未保管」と報告する
