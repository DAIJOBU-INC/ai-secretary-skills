# 公開前セルフレビュー

執筆後、ユーザーに見せる前に以下を確認し、直してから提示する。`context/owner/writing-style.md` に数値の目安が書いてあればそちらを優先する。無ければ以下をデフォルトの目安にする。

## 1. 語尾・表現の多様性(最優先)

- [ ] 同じ語尾(文末表現)が3文以上連続していないか
- [ ] 特定の語尾パターンだけに偏っていないか(5種類以上をローテーションできているか)
- [ ] 強い言葉(「エグい」「ヤバい」に類する強調語)を使いすぎていないか(目安: 1記事あたり各1〜2回まで)
- [ ] 記事タイプに合った温度感になっているか
- [ ] ビフォーアフター（以前→今、使う前→使った後）の対比で、変化が具体的に見えるか（目安: 1記事に2回ほど）
- [ ] 擬音語・擬態語など、場面が目に浮かぶ言葉が入っているか（文体ガイドで使う方針の場合。目安: 3回ほど）
- [ ] 見出しの数が内容に対して多すぎ・少なすぎないか（目安: 長めの記事で6個前後）

## 2. 導入の引き込み力

- [ ] 最初の3行で「何が得られるか」が明確か
- [ ] 想定読者が示されているか
- [ ] 導入パターンが記事テーマに合っているか
- [ ] 前置きが長すぎないか

## 3. 感情のうねり

- [ ] 各セクション内にフック→共感→転換→盛り上げ→着地の波があるか
- [ ] 平坦に情報を並べているだけのセクションがないか
- [ ] セクション冒頭に読者の注意を引く一言があるか

## 4. 口調の一貫性

- [ ] `context/owner/writing-style.md` のルールに違反している箇所がないか
- [ ] である調とです・ます調が混在していないか
- [ ] 記事タイプに合わないカジュアル/フォーマルな表現がないか

## 5. データ・根拠

- [ ] 主張の根拠が自分の実体験・実測になっているか(借り物の統計に頼っていないか)
- [ ] 数字は具体的か(「多い」ではなく倍率・件数・時間で)
- [ ] 効果数字が仮置き・創作になっていないか。未確認は `[要確認: 数字]` のままになっているか(残っていること自体はOK。ユーザーに埋めてもらう)

## 6. 読みやすさ

- [ ] 1文が長すぎないか(目安80文字以内)
- [ ] 短い言い切り文の「。」区切りが3つ以上連続していないか
- [ ] 難しい専門用語に言い換え・説明が添えてあるか
- [ ] 改行・空行が適切に入っているか

## 7. 実名・機密(必ず確認)

- [ ] 顧客名・取引先名・案件名が具体的に書かれていないか(仮名・役職名になっているか)
- [ ] 同僚・メンバーの実名が入っていないか
- [ ] 金額・契約条件・社外秘の数字が入っていないか
- [ ] 社内特有のツール名・URL・IDがそのまま書かれていないか(読者が再現できない情報になっていないか)

## 8. 差別化

- [ ] 過去に書いた記事と主張・構成が被っていないか
- [ ] 自分にしか書けない視点(実体験・実感)が入っているか
- [ ] 過去記事で使った具体的な数字を使い回していないか

## 9. 編集残骸の掃除

- [ ] 装飾記法の残り(太字記号・画像挿入指示など、媒体に応じて不要なもの)が残っていないか
- [ ] 「[修正まだ]」のような作業メモが残っていないか
- [ ] タイトル候補の書き残しが本文に残っていないか
- [ ] 署名・フッターを入れない方針なら、入っていないか確認

## 提示前の最終チェック(構成レベル)

文単位の確認とは別に、記事全体としてもう一段引いて確認する。

- **洞察の深さ**: 表面的でなく、読者に新しい気づきを与えているか
- **論理の明快さ**: 論理の飛躍がなく、読者がスムーズに理解できるか
- **So What?の強さ**: 読者が読後に何かしら行動・見方を変えられるか
- **構成の完成度**: 導入→展開→結論の流れが自然か

## レビュー結果の提示のしかた

- 完成原稿(全文)
- レビューで直した点の要約(2-3行)
- 「問題なければ保存します」の確認(投稿は提案しない。投稿操作はユーザー本人が行う)

**ここでのAI自身の合格判定は公開の許可ではない。** 保存前の最終承認は必ずユーザー本人から得る。
