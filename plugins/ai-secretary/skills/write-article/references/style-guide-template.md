# 文体ガイドの作り方(`context/owner/writing-style.md`)

write-article スキルは、この文体ガイドを読み込んで初めて「あなたらしい文章」を書ける。無い状態で書かせると、誰が書いても同じような当たり障りのない文章になる。最初に1回、時間をかけて作る価値がある。

## 作り方

### ステップ1: 過去に書いた文章を3〜5本集める

できれば種類の違うものを混ぜる。

- ブログ・note・SNS投稿
- 社内向けのメッセージ(全体連絡・提案文など、少し畏まったもの)
- 商談やプレゼンで使った話し言葉に近い原稿
- メール・チャットでの長めの説明文

全文をそのまま渡す(要約させない)。短い断片より、ある程度まとまった長さの文章の方が癖が出やすい。

### ステップ2(強く推奨): 下書きと公開版のペアがあれば集める

もし「自分で書いた下書き」と「実際に公開した最終版」の両方が残っている文章があれば、それも渡す。この2つを見比べると、自分が**毎回無意識に直しているパターン**が具体的にわかる(強すぎる表現を削る、仮の数字を実測に差し替える、前置きを削る、等)。これは文体ガイドを作る上で最も効く材料になる。3〜5組集まれば、それだけで「自分がいつも直している癖」の節を1つ作れる。

### ステップ3: 抽出する(AIに手伝わせてよい)

集めた文章を渡して、以下を1つずつ質問・整理してもらう。

- **一人称・呼称**: 「私」「僕」等。読者をどう呼びかけるか(「みなさん」「あなた」等)
- **語尾・口調パターン**: よく使う文末表現を5〜10個。テンションが上がったとき/落ち着いているときで使い分けているか
- **独自の表現**: 決まり文句、比喩、造語、繰り返し使う言い回し
- **禁止・避けている表現**: 絶対に使わない言い回し(硬すぎる敬語、特定の言葉遣い等)
- **文章のリズム**: 1文の長さの目安、である調かです・ます調か、改行や空行の頻度
- **導入の型**: よく使う書き出しのパターン(結論から入る/挨拶から入る/問いかけから入る 等)
- **締めの型**: 記事の終わり方、CTA(行動喚起)を入れるかどうか
- **数字・エビデンスの使い方**: 実体験ベースで語るか、データ・引用も使うか。使う場合はどの程度
- **タイトルの付け方の癖**: 数字を入れる、疑問形にする、等

下書き→公開版のペアがある場合は、差分から「毎回削られる要素」「毎回足される要素」も抜き出して別の節にする。

### ステップ4: `context/owner/writing-style.md` に書き出す

以下の雛形を埋める。使わない節は削ってよい。埋まっていない節よりは、節ごと無い方がよい(空欄のまま残すと参照する側が誤読する)。

```markdown
# 執筆スタイルガイド

## 基本プロフィール
- 名前・呼び名:
- 肩書・立場:

## 一人称・呼称
- 一人称:
- 読者への呼びかけ:
- 他者への言及のしかた:

## 語尾・口調パターン
(頻出パターンを5〜10個。テンション別に分類できるとなお良い)

## 独自の表現
(決まり文句・比喩・造語)

## 禁止表現
(使わない言い回し・避けている癖)

## 文章のリズム
- 1文の長さの目安:
- である調 / です・ます調:
- 改行・空行の頻度:

## 記事タイプ別の温度感
(記事の種類によってテンションを変えているなら記載)

## 導入パターン
(よく使う書き出しを2〜3パターン、例文つきで)

## 締め・CTA
(記事の終わり方の型)

## 数字・エビデンスの使い方
- 効果数字は実測を使う(仮置き禁止)。未確認なら `[要確認: 数字]` で残す
- 外部データを引用する場合の方針:

## 実名・機密
- 実名を出さない対象(顧客・取引先・同僚など):
- 社外に出さない情報:

## 下書きで毎回直される要素(あれば)
(下書き→公開版の差分から見つけたパターン)
```

## 公開後の育て方

1回作って終わりにしない。記事を公開するたびに、公開前の下書きを残しておく。時間があるときに、公開版と見比べて「今回も直された点」があればガイドに1行足す。これを数回繰り返すと、AIが書く下書きが少しずつ「自分の手直し」に近づき、直す量が減っていく。

## Gotchas

1. **文章が少なすぎると平均的な文章になる**: 1本だけから抽出すると、その1本のたまたまの特徴と本当の癖の区別がつかない。最低3本、できれば毛色の違うものを混ぜる
2. **他人の文章を混ぜない**: 誰かに添削してもらった後の版や、他人が代筆した文章を「自分の文章」として渡すと、文体ガイドが本人の癖とズレる
3. **雛形の空欄は消す**: 「(記載なし)」のまま残すと、write-article 側がそこを「意図的に空」と誤読して変な出力になることがある。使わない節は節ごと削る
