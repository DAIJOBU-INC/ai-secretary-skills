# 日報 — 1日の終わりに記録する

1日の作業を、完了・進行中・持ち越し・気づきの4つに整理して記録する。持ち越しは翌朝の daily-schedule（このパック）が拾う。

打ち合わせの内容をそのまま議事録として貼りたいだけなら meeting-notes（このパック）。本スキルは1日全体の作業ログ。

## 使い方

引数無し。その日の終わり（夕方〜夜）に実行する想定。

## 手順

1. **材料を集める**（つながっているものだけ使う。つながっていないものは黙って飛ばさず「使えなかった」と書くか、貼ってもらう）

   | 材料 | 内容 | 使えない・無いとき |
   |---|---|---|
   | カレンダー（Google カレンダー／Outlook など） | 今日実際に参加した会議 | 参加した会議を教えてもらう |
   | 議事録ツール（Circleback、Teams や Zoom の文字起こし など） | 今日のMTG記録（要点・アクションアイテム） | 文字起こしやメモを貼ってもらう |
   | メール（Gmail／Outlook など）・チャット（Slack／Teams など） | 今日やり取りした中で重要なもの | 貼ってもらう |
   | work/ 配下 | 今日作成・更新したファイル（更新日時で判定。gitを使っていればコミット履歴も使える） | 今日やった作業を教えてもらう |

2. **整理する**: 完了タスク／進行中タスク／今日の会議と要点／重要なやり取り、の4カテゴリに振り分ける
3. **持ち越しを出す**: 今日終わらなかった作業を「持ち越し」として書き出す。タスク管理ツールがあれば起票を提案する。対話実行時はその場で起票案（内容・期日案）を出して確認する。定期実行（無人）時は候補を書くだけにして起票はしない（翌朝の daily-schedule が「要確認」として拾える形で残す）
4. **気づき・判断したことを書く**: 今日の作業の中で判断したこと・気づいたことを短く記す。会社として長く効きそうな判断（方針転換・大きな意思決定など）があれば `context/company/decisions.md` への追記を提案する。**kabeuchi（このパック）と同じ形で追記する**（末尾に追記するだけで、既存のエントリは変えない。ファイルが無ければ作る）:

   ```markdown
   ## YYYY-MM-DD [テーマ]

   **決めたこと:** [選んだ選択肢・方向性]
   **理由:** [決め手]
   **捨てた案:** [検討して見送った選択肢。無ければ省略]
   **見直す条件:** [いつ・何が起きたら再検討するか]
   ```

   分からない欄は省略してよい。対話実行時はその場で確認してから追記する。定期実行（無人）時は追記せず、判断の候補を「要確認」に残すだけにする（翌朝以降、本人が確認してから対話のときに追記する）

5. `work/daily/YYYYMMDD_日報.md` に保存する（1日1ファイル。保存先はCLAUDE.mdに別の指定があればそちらを優先する。フォルダが無ければ作る）
6. 記録した内容の要約を伝える

## 出力形式

```
## YYYY-MM-DD の日報

### 完了
- 

### 進行中
- 

### 持ち越し（翌朝の工程表が拾います）
- [ ] 内容（期日案があれば）

### 気づき・判断したこと
- 

### 要確認
- 材料が集まらなかった項目、判断を保留した項目
```

## ルール

- 同じ日に2回目を実行するときは、既にその日のファイルがあれば上書きせず、追記するか確認してから進める
- 議事録ツールの要約だけで数字・固有名詞を書かない。気になる数字は元の記録に立ち返って確かめる（meeting-notesと同じ原則）
- 持ち越しは翌朝そのまま読まれる前提で書く。「あとで確認」のような曖昧な文で終わらせない

## 定期実行にするなら

終業後に自動で回すと、翌朝の工程表がすぐ持ち越しを拾える状態になる。使える環境ならスケジュール機能で「平日の夜◯時」に登録する。定期実行では持ち越しの起票や判断の確定をその場で聞けないため、候補を書き出すところまでにする。

## Gotchas（過去にハマったケース）

1. **その日AIと一緒に行った作業を数え忘れる**: 会議や送受信したメールにばかり目が行き、ファイルの作成・更新やその場でのやり取りが日報から漏れることがある。work/ 配下の更新も必ず材料に含める
2. **同じ日に2回実行すると上書きしてしまう**: 手動で1回、定期実行でもう1回のように同じ日に2回走ると、後から実行したほうが前の記録を消してしまうことがある。既に当日分のファイルがあるかを最初に確認する
3. **持ち越しを同じ文言で何日もコピーし続けると塩漬けになる**: タスク管理ツールがあれば早めに起票し、無い場合も同じ項目が3日以上残っていたら気づけるようにしておく
4. **他の自動化タスクの「0件」報告をそのまま信じない**: 同じ情報源を別のタスクが先に検索して「0件」と報告していても、取得タイミングのズレで結果が変わることがある。日報用には自分でも一度検索し直す
5. **定期実行が大きく遅れて走ったときはシステム日付をそのまま対象日にしない**: 深夜や翌朝にずれ込んで実行された場合、システム上の「今日」を対象日にすると実際の作業がほぼ無い空疎な日報になる。直近に実データがある日を対象日として扱う
