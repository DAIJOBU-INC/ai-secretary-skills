# 議事録 — そのまま貼れる形で出す

打ち合わせ・商談・MTGが終わった話が出たら使う。入力は会議録音ツール（Circleback など、接続されていれば）の記録、録画の書き起こし、手元のメモのどれからでもよい。

**読む人はその場にいなかった人。5分で追いつけることがすべて。**

だから、話した順ではなく**話題ごと**にまとめ、**次に誰が何をするか**で終わる。

---

## 出す形

**必ずコードブロックに入れて、丸ごとコピペできる状態で出す。**
中身はプレーンテキスト。`#` や `**` は使わない（Slackなどに貼ると記号がそのまま出てしまう）。

見出しは `■`、箇条書きは `・`。これならSlack・Teams・メール・Notion・Wordのどこに貼っても崩れない。

**まず、本文と社内メモの2つを作る。**

- 貼り先がまだ分からないときは、聞かずに、この2つを出す。取引先名は本文に入れておき、外部の人が見える場所に貼ると決まったら、表で名前を外して作り直す
- 貼り先が分かっているときは、「外に出すときに削るもの」の表で、その貼り先向けの版にして出す。社内メモのブロックは、控えにだけ入れ、会話には出さない（社内チャンネル向けの版には、表で「書く」ものだけを足す）
- 控えは、どちらのときも、この2つで作る

1. **本文（相手に見せてよい部分）** — 貼る用。次のものは入れない
   - 金額・単価の数字と、値引き・原価の話。費用の話題があったことは書いてよい。数字は〔金額〕に置き換える（置き換え方は「4. 相手の言葉はそのまま残す」）
   - 技術的な機密（顧客システムの方式・接続の仕組み・データの形式など）。中身は書かず、話題があったことと、話題の結論（認識が合った・要確認など）だけ書く
   - 社外の人が参加した打ち合わせ（商談・取引先・提携先など）では、こちらの見立て（営業上の作戦・人物評価・相手の温度感）。ただし、相手の発言そのものは、上の2つに当たる所を除いて、入れてよい
2. **社内メモ** — 本文に入れなかったものだけを書く。貼らない。本文に入れてよいか迷ったものも、ここに書く。先方が退出したあとの自社内の会話も、本文には入れず、必要なものだけここに書く。入れなかったものが無ければ、出さない

本文はこの形。

````text
【打ち合わせの名前】
YYYY/MM/DD HH:MM-HH:MM（オンライン／対面・場所）
先方：〇〇様・〇〇様（部署）／自社：〇〇・〇〇

■ 背景
・なぜこの打ち合わせが設定されたか。相手が何を知りたくて来たか

■ （実際に話題になったこと）
・

■ （実際に話題になったこと）
・

■ 結論・宿題
・結論（合意したことだけ。無ければ書かない）
・自社の誰：何を、いつまでに
・相手：何を、いつまでに
````

**■ 背景は、書いてあるときだけ書く。**元ネタ（文字起こし、貼られた予定の説明やメモ）か、本人から聞いた話に出てくれば書く。どこにも無ければ、この節ごと省く（背景のために、本人に聞き返さなくてよい）。推測で埋めない。期限は「期限の言及なし」と書くが（下の「5. 宿題は3点セット」）、背景は無くても宿題の追い方が狂わないので、書かずに省く。

社内メモはこの形。話に出なかった行は書かない。相手の温度感は、打ち合わせの終わりの時点のものを書く。複数に当たるときは、並べて書く（例：前向き。ただし持ち帰り）。

````text
【社内メモ】打ち合わせの名前
・相手の温度感：前向き／持ち帰り／断り（理由を一行で）
・金額・単価・値引き・原価の話：
・営業上の作戦・人物評価：
・技術的な機密：
````

## 節の立て方 — ここがいちばん大事

⛔ **テンプレの節を用意して埋めるのは禁止。話題になったものだけを節にする。**

「アジェンダ」「決定事項」「その他」のような固定の型に流し込むと、**話していないことを埋めるために推測が混ざる。**議事録で最もやってはいけないこと。

✅ 正しいやり方は、文字起こしを読んで**相手が実際に時間を使った塊**を見つけ、その名前を節にすること。

- 相手が費用の話に5分使ったなら `■ 費用`
- セキュリティの質問が続いたなら `■ セキュリティ`
- 納期で揉めたなら `■ 納期（最大の論点）` ← **論点であることを見出しに書く**

「（最大の論点）」を付けるのは、1回の打ち合わせで1つまで。次の順で決める。時間が長かっただけでは付けない。

1. 意見が分かれた話題、または相手が難色を示した話題（揉めた話題）。複数あるときは、先に出た話題に付ける
2. 揉めた話題が無いときは、このあとの宿題・次の約束がいちばん多く生まれた話題
3. どちらもはっきりしないとき（同数のときも）は、どの節にも付けない

節の数は3〜6個が目安。1つの節が1行しかないなら、その節は要らない（ほかの節に畳む。■ 背景と ■ 結論・宿題は、1行でも残す）。

**節の順番は「相手が知りたかった順」。**自社が話したかった順ではない。相手が知りたかった順が決められないときは、話に出た順にする。

## 中身の作り方

### 1. 元ネタを取る

会議録音ツール（Circleback など）が接続されていれば、そこから要約・アクションアイテム・参加者・**文字起こし本体**を取得する。

**無い場合**：録画の書き起こし、チャットログ、手元のメモを貼ってもらう。
**何も無いときは作らない。**「元になるものがありません」と言って、記憶で書かない。

### 2. ⛔ 要約だけで書かない

**AI要約は、文字起こしに存在しない数字を書くことがある。**（実例：料金プランの月額のような具体的な数字が要約にだけ登場し、実際の会話には一度も出てこなかったことがあった）

**要約は地図。本体は文字起こし。**
議事録に書く数字・固有名詞・日付は、**すべて文字起こしの中に実在することを確かめてから書く。**（録音ツールの会議情報にある日時・参加者・役職も、元ネタとして使ってよい）
日付は、「今週金曜」のような言い方で出てくるものも、その言い方が文字起こしにあれば実在する（日付への直し方は「5. 宿題は3点セット」）。
確かめられないものは、書かないか「未確認」と添える。

### 3. ⛔ 話者ラベルを信用しない

**自動文字起こしの話者判定は普通に間違う。**（実例：先方担当者の発言が、自己紹介から最後まで全部自社側の名前でラベルされていたことがあった）

**誰の発言かは、ラベルではなく中身で判断する。**
「弊社としては」「御社の」がどちら向きか、自己紹介の内容、質問しているのはどちらか。
**ラベルのまま引用すると、相手の要望を自社の発言として記録することになる。**

### 4. 相手の言葉はそのまま残す

要約すると温度が消える。**判断に効く一言はカギカッコで原文のまま入れる。**

- ✅ 「正直、年内は厳しいと思ってます」
- ❌ 「納期には慎重な姿勢」

言い淀み・重複だけ落として、言い回しは変えない。

**ただし、カギカッコの中に金額・単価・技術的な機密が入っているときは、本文（と、貼り先向けの版）では、その部分だけを〔金額〕〔技術情報〕のように置き換える。**発言の残りは原文のまま残し、置き換えたことが読む人に分かるよう〔 〕で示す（黙って削らない）。置き換える前の原文は、社内メモと控えにだけ書く。置き換えると意味が残らない一言だけは、貼り先向けの版では、その一言ごと外してよい。

- 原文：「正直、〇〇万円を超えると社内で通せません」
- 本文：「正直、〔金額〕を超えると社内で通せません」

### 5. 宿題は3点セット

**誰が・何を・いつまでに。**期限は、文字起こしで言われたとおりに書く。

- 日付で言われたら、その日付を書く
- 「今週金曜」「来週の火曜」のように、打ち合わせの日から日付がひとつに決まる言い方は、日付に直し、言われた言葉を添える。例：打ち合わせが10/1（木）で「今週金曜」と言われたら、10/2（金）※「今週金曜」
- 「今週中」「月末」「来週の頭」「近いうちに」「あとで」「〇〇をいただいたら、すぐに」のように、日付がひとつに決まらない言い方は、日付に直さず、言われた言葉のまま書く
- 期限が出ていなければ「期限の言及なし」と書く。勝手に決めない

「何を」が発言から決まらないときも、補わない。言われたとおりに書く（例：「上に確認して、返事する」）。

自社側と相手側を分けて書く。相手の宿題を書き落とすと、催促する根拠がなくなる。

## 出したあと

1. **控えを残す** — 本文と、あれば社内メモを、コードブロックの囲みごと、1つのファイル `work/mtg/YYYYMMDD_議事録_<打ち合わせ名>.md` に保存する（フォルダが無ければ作る。囲みごとにするのは、あとで開いたときに行が崩れないため）。打ち合わせ準備の資料と同じ場所に並べる
   - `YYYYMMDD` は打ち合わせの日。`<打ち合わせ名>` は、本文の1行目の【】の中の言葉から、敬称（様・さん）・担当者の名前・金額を除き、空白を詰めて、20字以内にしたもの。例：`20261001_議事録_週次定例.md`
   - 貼り先に合わせて作り直した版は、ファイルには保存せず、会話に出すだけにする。控えは打ち合わせごとに1つだけにする（削った版を、全部入りの控えと取り違えないため）
2. **取引先とのMTGなら記録を直す** — 相手の状況・温度感・次の約束が変わったら `context/clients/<相手先>.md` を更新する（顧客台帳のようなデータベースがあれば、そちらの更新要否も確認する）。議事録そのものはその場の記録、**変わった事実だけ**を積み上げ用のファイルへ移す
3. **送るのは人** — メールの送信と、チャット（Slack・Teamsなど）への投稿は、AIではなく、あなたが自分で行う。このスキルの仕事は「貼れる形を作る」ところまで。「送って」「OK」と言われても、AIは送信・投稿・転送・予約送信をせず、文面を提示したところで止まる

### 取引先のカルテ（`context/clients/<相手先>.md`）の直し方

上の2の進め方。ここでいう取引先には、商談中でまだ発注前の相手と、提携先も含む。社内メンバーとの会議・1on1は対象外。

1. `context/clients/` で、同じ会社のファイルを探す（「株式会社」の有無や略称の違いも見る。フォルダが無ければ作る）
2. **あれば**、「商談の状況」の欄を、変わったことに合わせて直す。先頭の `updated:` を今日の日付にする。ほかの欄は書き換えない。ファイルに「商談の状況」の欄が無ければ、末尾に足す
3. **無ければ**、聞かずに、会社名（「株式会社」などは付けない）のファイルを下の形で新しく作り、作ったことと場所を本人に1行で伝える。基本情報などの調べものの欄は、あとで「〇〇のカルテをつくって」と頼まれたときに company-research が足す
4. 似た名前（「〇〇商事」と「〇〇商会」のように、一部だけ同じ名前）のファイルがあり、同じ会社か分からないときだけ、作る前に本人に聞く
5. 上の2にある「顧客台帳のようなデータベース」は、使っていると分かっているとき（`CLAUDE.md`・プロフィール・本人の話で分かるとき）だけ扱う。そのときは、更新が要るかを本人に1行で聞く。使っているか分からないときは、探しにいかず、聞かない

```markdown
---
updated: YYYY-MM-DD
---

# 会社名

## 商談の状況

- 状況・温度感:
- 次の約束（誰が・何を・いつまでに）:
- 直近の打ち合わせ: YYYY-MM-DD（議事録: `work/mtg/YYYYMMDD_議事録_打ち合わせ名.md`）
```

## 外に出すときに削るもの

社内だけで読むもの（控えのファイル、社内メモ、取引先のカルテ）には、すべて書いてよい。**ただし、貼る・送る版は、貼り先に合わせて絞る。**

貼り先が決まったら、次の表で、その貼り先向けに作り直す。

| 書くもの | 相手に送る（メールなど、相手が見るもの） | 外部の人が参加している・見える・確かめられないチャンネル | 自分宛のDM・外部の人がいない社内チャンネル |
|---|---|---|---|
| 金額・単価の数字 | 書かない | 書かない | 書かない |
| 技術的な機密（顧客システムの方式・接続の仕組み・データの形式など） | 書かない | 書かない | 書かない |
| 値引き・原価の話 | 書かない | 書かない | 書く（金額・単価の数字は除く） |
| こちらの見立て：営業上の作戦（「ここが刺さった」「決裁者は誰か」）・人物評価（「リテラシーが低い」）・相手の温度感 | 書かない | 書かない | 書く |
| 取引先名・先方の人の名前 | 書く（相手の会社名・名前） | 書かない | 書く |

- **チャットの決まりが先。**金額・単価・技術的な機密は宛先によらず書かない。「社内だけで読むものにはすべて書いてよい」は、控えのファイル・社内メモ・カルテの話で、チャットに貼る文面には当てはまらない
- 表の「こちらの見立て」は、こちらの判断や評価のこと。相手の発言そのものは見立てではないので、金額・技術的な機密を除いて、「相手に送る」版にも「社内だけ」の版にも入れてよい
- 「相手に送る」ときは、本文だけを使う。社内メモは送らない。相手自身が言った金額入りの発言は、〔金額〕で残さず、外す（金額の話があったことだけ書く）。見出しの「（最大の論点）」の印も、こちらの見立てなので外す
- 先方の人も参加している共有チャンネルは、先方以外の社外の人はいないと本人が言ったときだけ、「相手に送る」の列を使う。言われていないときは、外部の人がいるものとして扱い（右から2番目の列）、先方以外の社外の人がいないかを、本人に1回だけ聞く
- 「自分宛のDM・外部の人がいない社内チャンネル」向けは、本文の「■ 結論・宿題」の前に「■ 社内メモ」を足した1つの版にする（議事録は、次に誰が何をするかで終わる）。足すのは、社内メモのうち表で「書く」もの（相手の温度感、営業上の作戦・人物評価、値引き・原価の話）だけ。足す発言に金額・技術的な機密が入っているときは、4のとおり、その部分だけを〔金額〕のように置き換える（発言ごとは落とさない。意味が残らない一言だけは外してよい）。本文にすでにある発言は、重ねて足さない
- 「外部の人が参加している・見える・確かめられないチャンネル」向けは、取引先名も先方の人の名前も書けないので、件数・カテゴリだけに絞る（例：先方の人数、話題の名前、宿題の件数）。詳細は、保存した議事録ファイルを指すだけにする。ファイル名に取引先名が入っているときは、ファイル名を書かず、日付と `work/mtg/` で指す

**外部の人がいないことは、次の順で確かめる。**

1. 自分宛のDMは、確かめなくてよい
2. 本人が「社内チャンネル」「社内だけのチャンネル」のように、社内向けだと言ったら、その言葉を根拠にしてよい。聞き返さない。ただし根拠にできるのは、その言葉で指した貼り先だけ。貼り先が変わったら、あらためて確かめる
3. 社内向けだと言われず、チャンネル名だけ言われたときは、チャットの道具がつながっていれば、参加者と外部共有の設定を見て確かめる。見られなければ、本人に「そのチャンネルに社外の人（ゲスト・外部共有）はいますか」と1回だけ聞く。答えが来るまでの版は、4のとおり、外部の人がいるものとして出す
4. 確かめられなければ（定期実行などで聞けないときも）、外部の人がいるものとして扱い、取引先名を書かない

**同じ文面を使い回さない。**社内向けと対外向けは別物として作り直す。

## 使い分け

| 場面 | 使うもの |
|---|---|
| 打ち合わせの**前** | `mtg-prep`（このパック） |
| 打ち合わせの**記録を共有する** | **このスキル** |
| 1on1の**メンバーファイルへの書き戻し** | `1on1-writeback`（このパック） |
| 事後の**お礼・確認メール** | メール下書きスキル（このパックにあれば） |
| 議事録を**相手にメールで送る** | 中身は**このスキル**（「外に出すときに削るもの」の表の「相手に送る」）。メールの形（宛名・件名・装飾記号なし）は `reply-draft`（このパック）に従う |

議事録と振り返りは別物。「どう共有するか」がこのスキル、「うまくいったかどうかの評価」は別の仕事。

## 守ること

- ⭐ **コードブロックで、丸ごとコピペできる形で出す。**説明文の中に混ぜて書くのは「出した」ことにならない
- ⭐ **貼る本文に、金額・単価の数字と、技術的な機密を入れない。**外したものは社内メモに書く（入れてよいか迷ったものも社内メモ）
- ⭐ **推測を書かない。**話していないことは、どれだけ自然な流れでも書かない
- ⭐ **数字・日付・固有名詞は文字起こしで実在を確かめる**
- **議事録の前後に感想を長々と書かない。**気づいたことがあれば、コードブロックの外に短く
- **長さは相手が読む気になる量。**30分の打ち合わせなら、本文は30〜60行が目安。全部書くと誰も読まない。外したもので短くなるときは、足さない

## Gotchas（過去にハマったケース）

1. **要約だけで書くと存在しない数字が紛れ込む**: 料金プランの月額のような具体的な数字が、AI要約にだけ登場し実際の会話には一度も出てこなかったことがある。数字は必ず文字起こし本体で裏取りする
2. **話者ラベルは平気で入れ替わる**: 自動文字起こしで、先方担当者の発言が最初の自己紹介から最後まで自社側の名前でラベルされていたことがある。ラベルではなく発言の中身（敬語の向き・質問の方向）で話者を判定する
3. **テンプレ節に推測が混ざる**: 「アジェンダ」「その他」のような固定の節を埋めようとすると、話していないことを埋めるために推測が入る。話題になったことだけを節にする
4. **元ネタが無いのに雰囲気で書いてしまう**: 記憶や一般的な商談の流れから「たぶんこう言っただろう」と埋めると、事実と違う記録が残る。元ネタが無いときは作らず、何が必要かを伝えて止まる
5. **期限の無い宿題を勝手に決め打ちする**: 期限が言及されていないのに、なんとなく「1週間後」のように書いてしまうと、あとで催促するときの根拠が狂う。言及がなければ「期限の言及なし」とそのまま書く

## 詰まったとき

| 症状 | 対処 |
|---|---|
| 誰の発言かわからない | ラベルを疑う。自己紹介・敬語の向き・質問の方向で判定する |
| 要約と文字起こしが食い違う | **文字起こしが正。**要約にしかない情報は落とすか「未確認」と添える |
| 話が飛んで節にまとまらない | 相手が時間を使った順に並べ直す。時系列にこだわらない |
| 参加者名がわからない | わかる人だけ書いて、残りは人数だけ（「先方3名」）にする |
| 元ネタが何も無い | 作らない。何が必要か伝えて止まる |
| 貼り先が分からない | 聞かずに、本文と社内メモを出す。貼り先が決まったら、「外に出すときに削るもの」の表で作り直す |
| 貼り先が分かっていて、外部の人がいるか確かめられない | いるものとして扱い、取引先名を書かない（貼り先がまだ分からないうちは、取引先名を本文に入れておく） |
| ■ 背景が元ネタに出てこない | 本人から聞いた話にあれば、それを書く。どこにも無ければ、節ごと省く |
