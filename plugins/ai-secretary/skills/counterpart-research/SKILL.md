# 相手の下調べ — 資料は最後に作る

外部の相手に出すものを頼まれたら、**資料を作り始めない。** 先に相手を調べ、「今回当てはまるのはこれ」を本人と決めてから作る。
相手が本当に求めているものは、相手自身も言葉にできていないことがある。そこへ近づくために調べる。

`mtg-prep` との違い: `mtg-prep` は会議の直前に、社内の記録と相手の概要を集める。こちらは、提案の方向を決める前に相手を深く知るためのもの。初めての相手・大きな提案のときに使う。

`company-research` との違い: `company-research` は会社ごとのカルテを作って育てる（会社の事実が中心）。こちらは1回の提案のために、キーパーソン本人の発信まで読み、「今回どこに当てるか」を決めるところまで進める。確かめられた会社の事実はカルテにも足す。

## 順番（崩さない）

1. **こちらの目的を1行で固定する**
   - 例: 「この相手から見積もり依頼をもらう」「紹介元になってもらう」
   - 調べるうちに相手の関心が見えても、この目的は書き換えない。相手の情報は、目的に近づく方法を選ぶために使う
   - 誰から・何を・いつまでに、を書き出す。人から聞いた相手像（「AIには詳しくない人らしい」など）は、確かめる対象として置く
2. **相手を調べる**（下の「調べる観点」から、目的に効くものを選ぶ）
3. **レポートを出して、いったん止まる**。本人と「今回当てはまるのはこれ」を決める
4. **提案の芯を決める**: 相手が大事にしている言葉を1つ／提案の中心を1文／小さく試す形
5. **決めた芯を渡す。** 資料づくりは次の依頼で（会議の資料なら `mtg-prep`、記事なら `write-article`）

急ぎでも2と3は飛ばさない。時間がないときは下の「30分版」で回し、調べていない観点を書いておく。
資料を先に作りたくなったら、「今回当てはまる提案」を1文で書けるか確かめる。書けないなら、調べ足りていない。

## 調べる観点（全部をレポートに並べない）

| 観点 | 見るもの |
|---|---|
| A 業界の基本 | その業種がふだん何をしているか（主な仕事5つ程度）／本質的に何を売っているか／収益の形（顧問料・スポット・成功報酬など）／法律や規制で言ってはいけないこと |
| B 会社の基本 | 正式名称・代表・所在地・設立年・所属団体／サービスと公開価格。出典ごとに食い違う情報は両方と出典を書く |
| C 顧客 | 公開されている業種・規模・地域・事例（いつ時点の掲載か）。そこから立てる顧客像は仮説として書く |
| D キーパーソン | 経歴・著書・登壇／**本人の発信（note・ブログ・SNS・インタビュー・動画）を新しい順に読む**。繰り返し使う言葉・大事にしている考えを引用で抜く。仕事に関係する公開情報だけを見る（家族・私生活は調べない）。古い情報は年を書く |
| E 業者の選び方 | 導入事例やお客様の声で、本人が何を評価しているか（速さ・小さく試せる・提案力など） |
| F すでにやっていること | 関連会社・副業・既存サービスのうち、こちらの提案と重なるもの。競合か補完かを分ける。本人がすでに実践していることと同じデモを見せない |
| G つながり | 所属団体・講師先・共催相手。「顧客」と「つながり」を分ける（所属していても紹介してもらえるとは限らない） |
| H 制度・規制 | 助成金・法律・個人情報・利用規約など、今回の話に効くものを一次情報で最新まで確認する。助成金などは断定しない |
| I 分からないこと | 顧客数・売上・予算・今回の本当の意図など、公開情報で分からないものを並べる |

## レポートの型（本人に出すもの）

長いレポートは読まれない。**事実 → 解釈 → 行動** のセットで5〜8項目にする。

```
こちらの目的: （1行）

1．（見出し＝この項目で言いたいことを1文で）
・事実: 確認できたことだけ。出典の種類（公式・第三者・本人の発信・伝聞）が分かる書き方で
・解釈: その事実から、こちらの目的にとって何が言えるか
・行動: だから何をするか。誰に何を聞くか

（5〜8項目まで。1項目は1つの話題）

まとめ: 今回の提案（目的・入口・流れ・資料の方針）
本人に決めてほしいこと: （あれば）
```

- 1項目の中で事実・解釈・行動を混ぜない。解釈の無い事実、行動の無い解釈は、項目ごと削る
- 出典一覧・読んだ記事の一覧・細かい数字は別ファイルに分ける。聞かれたら出す
- 返答では、まとめと本人に決めてほしいことを先に出す

## 保存

- レポート: `work/research/YYYYMMDD_<相手の短い名前>_下調べ.md`、詳細: `work/research/YYYYMMDD_<相手の短い名前>_詳細.md`
- 取引先のカルテ（`context/clients/<相手先>.md`）へ足すのは、確認できた事実だけ。足す前に本人に聞く
- 前に調べた相手は、前回の調査日からの差分だけ調べ直す

## 書き方のルール

- 事実・相手の自己申告・第三者の掲載・推測を分ける
- 数字には「誰が・いつ時点で出した値か」を付ける。過去の実績を今の数と混同しない
- 同姓同名を混ぜない。その会社との関係が確かめられた情報だけ使う
- 別のAIや人の調査結果を受け取ったら、主な事実を一次情報で確かめてから使う。確かめていない部分は「未確認」と書く

## 守ること

- 公開情報だけを使う。ログインが要る場所・鍵付きのSNS・家族や私生活には踏み込まない
- 調べたことをひけらかさない。会ったときの切り出しは、相手の実践を認める一言から
- 相手の今の仕事を奪う提案にしない。相手が得るものと、相手の負担が増えすぎないことをセットで示す
- 問い合わせ・送信・フォームへの入力はしない

## 30分版（急ぎのとき）

- A 業界の基本（主な仕事と、言ってはいけないこと）
- D 本人の最新の発信3本と、大事にしている言葉
- F すでにやっていること
- 事実→解釈→行動を3項目まで＋まとめ。調べていない観点は「未調査」と書く

## 進め方のコツ

- 調査は分けて並行できる（会社と顧客／本人の発信／業界と制度）。使える環境ならサブエージェントに任せる
- note やブログは記事一覧を新しい順に読む。タイトルだけで判断しない
- 社内の記録（メール・チャット・`context/clients/`）も合わせて見る

## Gotchas（過去にハマったケース）

1. **人から聞いた相手像だけで、企画書とチラシを先に作ってしまった**: 「ITに詳しくない代表」と聞いて入門向けの資料を作ったら、実際の代表は自分で業務の自動化を進め、関連会社で同じ分野の支援もしていた。前提が崩れ、資料を作り直した。相手本人の発信を先に読んでいれば防げた
2. **18項目の長いレポートを出して、読まれなかった**: 調べた観点を全部並べると、読む側の負担が大きすぎる。事実→解釈→行動のセットで5〜8項目に絞る
3. **相手の関心に引っ張られて、こちらの目的をすり替えた**: 調べるうちに相手の話に寄り添いすぎて、「こちらの商談につなげる」目的が「相手の活動を手伝う」にすり替わった。目的は最初に1行で固定し、書き換えない
