# 読書ガイド

本のタイトルを受け取り、あなたの読書を最大化する「パーソナル読書アドバイザー」。
単なる要約ではなく、**読む前の準備（読み方ナビ）と読んだ後の実践化（アクション＋内省＋振り返り）の両方**を支援する。

## 引数

| 呼び方 | 動作 |
|---|---|
| `/reading [書名]` | 通常モード（Phase 1〜5） |
| `/reading` | Phase 0 — 積読リストから次の1冊を提案する |
| `/reading [書名] --review` | Phase 6 — 実践の振り返りモード |

## Phase 0: 引数なしのとき（積読リストから提案）

`context/owner/reading_list.md` があれば読み、「読みたい本」から2〜3冊を選んで提案する。
選ぶ基準は**いまの優先事項との距離**。`context/owner/profile.md`（あれば）を見て、いまぶつかっている論点に効きそうな順に並べる。

「なぜ今これか」を1冊1行で添えて提示し、選んでもらってから Phase 1 へ進む。
リストが無い・空・全部ピンとこないと言われたら、いまの課題を聞いて本を提案する。

## Phase 1: コンテキスト収集（最初に・省略不可）

ユーザーに質問する前に、以下を読み込む:

1. `context/owner/profile.md`（あれば）— あなたの価値観・優先事項・仕事の進め方
2. `context/company/overview.md`（あれば）— 事業内容・用語
3. 同じ本の過去ガイドがあれば必ず読む（`work/reading/`）。存在する場合は再読なので [review-format.md](references/review-format.md) の再読フォーマットに従う

**1・2 のファイルが両方とも無ければ、Phase 2 のヒアリングに次の質問を追加する**: 「どんな仕事をしていますか？」「チームの規模・構成は？」

## Phase 2: ヒアリング（省略不可）

以下を確認する:

- 「この本を手に取った理由・きっかけは？」
- 「今の仕事で特にぶつかっている壁や、考えたいテーマは？」
- 「これから読む？もう読んだ？途中？」
- （Phase 1 で context ファイルが無かった場合のみ）「どんな仕事をしていますか？」「チームの規模・構成は？」

回答に応じて Phase 4 の出力の重心を調整する（詳細は [output-format.md](references/output-format.md) の重心調整ルール）。

## Phase 3: リサーチ

Web検索で以下を調べる（最低5クエリ目安）:

1. 本の章構成・主要コンセプト・著者の背景
2. 質の良い結果2〜3件を詳しく読む
3. 書評・批判的視点も収集する（この本の限界・前提を把握する）

結果を `work/reading/research/YYYYMMDD_research_[書名].md` に保存する。

**このリサーチファイルは消さない。** 批判的視点・著者背景は再読のときに効く資産なので、ガイド完成後もそのまま残す。

## Phase 4: 出力生成

[output-format.md](references/output-format.md) を読み、その雛形に沿って生成する。
Phase 1で集めた状況、Phase 2のヒアリング結果、Phase 3のリサーチを統合する。

品質基準（「あなたの仕事では」を汎用記述にしない・アクションを具体化する等）も同ファイルに記載。

## Phase 5: ユーザー確認＆保存

1. 出力全体をユーザーに提示する
2. フィードバックがあれば修正する
3. 承認後、`work/reading/YYYYMMDD_読書_[書名短縮].md` に保存する（`work/reading/` が無ければ作成する）
4. `context/owner/reading_list.md` があれば更新する — 読んだ本を「読みたい本」から「読了済み」へ移し、ガイドへのリンクを張る
5. **振り返り日をユーザーに確認する（デフォルト: 2週間後）。この日付をガイド末尾に `<!-- review-due: YYYY-MM-DD -->` の形式で埋め込む。** この日をカレンダーやリマインダーに入れておく（定期的にチェックする仕組みがあればそれに任せてもよい）。ここを省くと振り返りが実行されないまま終わりやすい

## Phase 6: 実践フォローアップ（`--review`）

[review-format.md](references/review-format.md) に従う。セクション6のアクションを1件ずつ確認し、セクション8として追記する。
追記したら該当ガイドの `<!-- review-due: ... -->` マーカーを削除する（未振り返り扱いから外すため）。

|---|---|---|

## Gotchas（過去にハマったケース）

1. **生成物の扱いに注意する**: ガイドの「あなたの仕事では」セクションは、実践のために具体的な人物・状況を名指しで含むことが多い。機密性が上がりやすいので、社外に共有する資料へそのまま転記しない
2. **振り返り日をファイルに埋め込まないと振り返りが実行されない**: 「読んで終わり」を防ぐ仕組みは、発火のきっかけ（マーカーやリマインダー）が無いと機能しない。Phase 5 の `review-due` マーカーは必須
3. **再読を別ファイルで作らない**: 同じ本を読み直すたびに別ファイルを作ると、関心の変遷が追えなくなる。1冊1ファイルに統一し、既存ガイドに追記する
4. **リサーチ成果物を消さない**: 批判的視点・著者背景は再読時の資産になる。要約が完成した後も削除せず残す
5. **`context/` の参照先が無いことがある**: Phase 1 で読めないファイルがあっても止まらず、あればある分だけ使い、無ければヒアリングで補う

## 注意事項

- 出力はMarkdown形式（見出し・太字・引用ブロック・箇条書きを使って読みやすく整形する）
- 本スキルは「読んで終わり」を防ぐのが主目的。ガイド生成だけで満足せず、必ず振り返り日まで設定して閉じる

## 使い方

```
/reading                          # 積読リストから提案してもらう
/reading HIGH OUTPUT MANAGEMENT
/reading イシューからはじめよ
/reading 影響力の武器 --review     # 実践の振り返り
```
