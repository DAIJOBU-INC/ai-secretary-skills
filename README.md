# AI秘書スキルパック

Claude Code を「自分専用のAI秘書」として使うためのスキル集です。
経営者・マネージャーが毎日くり返す仕事（朝の段取り、受信箱の整理と返信、会議の準備と議事録、1on1の記録、判断の壁打ち、情報収集、発信、日報・週報）を、ひとことで頼めるようにします。

## 入っているスキル（15本）

| 場面 | スキル | 何をしてくれるか | こう頼む |
|---|---|---|---|
| 朝 | daily-schedule | 今日（または明日）の予定・タスク・前日の持ち越しから、15分刻みの工程表を作る。準備資料が無い会議も教えてくれる | 「今日の工程表をつくって」 |
| 受信箱 | inbox-triage | メールとチャットで、自分宛てにまだ返していないものを洗い出し、優先度をつけて一覧にする | 「返信漏れてない？」 |
| 受信箱 | reply-draft | 受信メールへの返信を下書きする。チャットの返信文も作れる。日程調整は予定の空きから候補を出す（送信・投稿はしない） | 「このメールの返信を下書きして」 |
| 会議 | mtg-prep | 会議の前に、予定・過去の議事録・メール・チャット・手元のメモを集めて準備資料を作る。相手に見せてよい部分と社内メモの2部構成。1on1 の準備にも対応 | 「明日のA社との打ち合わせの準備資料をつくって」 |
| 会議 | meeting-notes | 議事録を Slack／Teams／メールにそのまま貼れる文面にする（送信はしない） | 「さっきの打ち合わせの議事録を出して」 |
| 会議 | 1on1-writeback | 1on1 の記録をメンバーごとのファイルに書き戻し、次の1on1につなげる | 「今日のAさんとの1on1を記録して」 |
| 考える | kabeuchi | 仮説や迷いをぶつけると、反論・見落とし・第3の道を出して、最後に判断を3行でまとめる。決めたことは判断の記録に残せる | 「この方針で壁打ちしたい」 |
| 調べる | company-research | 取引先・商談相手・提携先を調べて、会社ごとのカルテを作る・更新する | 「A社のカルテをつくって」 |
| 調べる | reading | 本の要点をつかみ、自分の仕事への実践ガイドにする。読んだ後の振り返りも | 「この本をまとめて」 |
| 調べる | clip | 気になった記事・URLを要約して、タグ付きで保存する | 「これをクリップして」 |
| 発信 | write-article | 自分の文体で、記事・発信文の下書きを書く（投稿は自分で） | 「このテーマで note の記事を書いて」 |
| 発信 | eli5 | むずかしい仕組みを、大きな絵と少ない言葉の「しくみ絵本」で説明する | 「◯◯を絵本で説明して」 |
| 夜 | daily-log | 1日の終わりに、やったこと・進行中・明日への持ち越しを日報にまとめる | 「今日の日報をまとめて」 |
| 週末 | weekly-report | その週の日報を束ねて、成果・進捗・課題・判断したこと・来週の注力を週次レポートにする。追っている数字があれば前週と並べる | 「今週の振り返りをつくって」 |
| 片付け | downloads-triage | ダウンロードフォルダを週1回仕分ける（消さずに移動。動かす前に確認） | 「ダウンロードを整理して」 |

ふだんは上の「こう頼む」のような自然な言葉で頼めば、Claude が合うスキルを選びます。名前を指定して呼ぶときは `/ai-secretary:mtg-prep` のように書きます。

## 入っているエージェント（1体）

| エージェント | 何をしてくれるか |
|---|---|
| researcher（調査係） | 手元のファイル・Web・つながっている道具を横断して調べ、要点と出典だけを返す。調べものを別の係に任せるので、会話が長くなっても散らかりにくい。道具は読むだけで、送信・投稿・予定の作成はしない |

company-research などのスキルが必要なときに使います。「調査係に任せて◯◯を調べて」と直接頼むこともできます。

## 入れ方

### A. プラグインとして入れる（おすすめ）

Claude Code（デスクトップアプリの Code タブ、またはターミナル）で、次の2行を順に入力します。

```
/plugin marketplace add https://github.com/DAIJOBU-INC/ai-secretary-skills.git
/plugin install ai-secretary@daijobu
```

- **このリポジトリが非公開の場合**: 先に GitHub の招待を受け、GitHub にログインしておく必要があります。Claude Code に「GitHub にログインして、プラグインを HTTPS で取れるように設定して」と頼むと、`gh auth login` と `gh auth setup-git` を案内してくれます
- **更新を受け取る**: `/plugin` の画面（Marketplaces）で `daijobu` の自動更新をオンにしておくと、スキルが直されたときに自動で届きます。オフのままなら、同じ画面から手動で更新します

### B. フォルダをコピーして入れる

`plugins/ai-secretary/skills/` の中から使いたいスキルのフォルダを、自分のリポジトリの `.claude/skills/` にコピーします（例: `.claude/skills/mtg-prep/`）。この場合の呼び名は `/mtg-prep` です。調査係も使うなら、`plugins/ai-secretary/agents/researcher.md` を `.claude/agents/` にコピーします。自動の更新はありません。

## 前提のフォルダ構成

AI秘書ビルダーで作るフォルダ構成と同じです。無いフォルダはスキルが作ります。`CLAUDE.md` に別の保存先を書いておけば、そちらが優先されます。

```
CLAUDE.md
context/                 今の事実（上書きで育てる）
  owner/profile.md       自分のプロフィール・価値観・仕事の進め方
  company/overview.md    会社の概要・事業・用語
  company/decisions.md   判断の記録（日付つきで追記。kabeuchi・daily-log が書き足す）
  company/kpi.md         追っている数字（あれば。weekly-report が読む。社外に出さない）
  clients/<相手先>.md     取引先ごとのカルテ（company-research が作る）
  members/<名前>.md       メンバーごとのファイル（1on1の記録など）
work/                    日々の成果物（追記で増える）
  mtg/  clips/  reading/  content/  research/
  mail/                  返信下書きの控え（残したいときだけ）
  daily/                 工程表・日報・未返信チェック
  weekly/                週次レポート
```

`context/` に書いてあることが多いほど、スキルの出来が上がります。まずは `context/owner/profile.md` と `context/company/overview.md` から始めるのがおすすめです。

## つながっていると便利な道具

| 役割 | 例 | つながっていないとき |
|---|---|---|
| カレンダー | Google カレンダー／Outlook | 予定を貼って伝える |
| メール | Gmail／Outlook | 必要なメールを貼る |
| 議事録ツール | Circleback／Teams や Zoom の文字起こし など | 文字起こしやメモを貼る |
| チャット | Slack／Teams | 必要なやり取りを貼る（LINE も貼れば使えます） |
| 資料置き場 | Google ドライブ／SharePoint・OneDrive | ファイルを手元に置く |

道具は Claude の「コネクタ」設定でつなげます。つながっていない道具について、スキルは黙って飛ばさず「使えなかった」と書くか、貼り付けをお願いしてきます。

## 毎日・毎週、自動で回すなら

慣れてきたら、次の組み合わせを Claude の定期実行（スケジュール）に登録すると、「朝起きたら工程表ができている」「夜には日報がまとまっている」状態になります。

| いつ | 何を |
|---|---|
| 平日の朝 | daily-schedule（工程表）と inbox-triage（未返信の洗い出し） |
| 平日の夜 | daily-log（日報） |
| 金曜の夕方 | weekly-report（週次レポート） |

夜の日報に書いた「持ち越し」を翌朝の工程表が拾い、金曜の週次レポートがその週の日報を束ねる、という1本の流れになっています。定期実行のあいだは誰にも質問できないので、確認が必要な点は成果物の「要確認」に書き残されます。朝のうちに目を通してください。

## 安全のための約束（全スキル共通）

- **メールは下書きまで。** 送信・転送・予約送信はしません。送信ボタンは自分で押します
- **チャットの投稿も文面を作るところまで。** 投稿は自分でします
- **相手に見せる部分と社内メモを分けます。** 共有してよい部分に、金額・社内での評価・社内の段取りは書きません
- **パスワード・APIキーなどの認証情報は読まない・書かない**
- 人の特定は「メールアドレスが同じ」だけで決めつけず、迷ったら確認します

## 困ったとき

- スキルが呼ばれない → `/ai-secretary:スキル名` で直接呼ぶ。`/plugin` の画面で有効になっているか確認する
- 自分で作った同じ役割のスキル（例: 自作の `/daily-schedule`）があって、どちらが動くか迷う → `/ai-secretary:daily-schedule` のように名前で指定するか、使わない方を無効にする
- 更新が届かない → `/plugin` の画面から `daijobu` を更新する

## メンテナンス（配る側向け）

- スキルを直したら、`plugins/ai-secretary/.claude-plugin/plugin.json` の `version` を上げます（上げないと利用者に更新が届きません）
- 変更したら `claude plugin validate .` で形式を確認します
- ここには一般化したものだけを置きます。社名・人名・金額・社内のIDは書きません
